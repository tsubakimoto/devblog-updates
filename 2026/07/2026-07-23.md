## The Microsoft 365 Copilot Agent’s Playbook: A Practical Livestream Series for Building Better Agents

## Move Agent Orchestration/Workflows out of Code with Agent Framework Declarative Workflows 1.0

- **Blog:** Agent Framework
- **Author:** Peter Ibekwe
- **URL:** https://devblogs.microsoft.com/agent-framework/move-agent-orchestration-workflows-out-of-code-with-agent-framework-declarative-workflows-1-0

### 要約
Agent Framework の declarative workflows が Python と .NET の両方で 1.0 に到達したことを知らせています。YAML でオーケストレーションを定義し、コードから分離してレビュー・変更しやすくするのが主眼です。

### 開発者にとって重要なこと
複数エージェントのフローをアプリコード内で組んでいるチームにとって、保守性とレビュー容易性に直結します。製品担当、アーキテクト、開発者が同じワークフロー定義を見ながら議論しやすくなります。

### アクションプラン
- 既存のマルチエージェントの制御フローを YAML 化できるか確認する。
- Python は `agent-framework-declarative`、.NET は `Microsoft.Agents.AI.Workflows.Declarative` の 1.0 系への移行を検討する。
- 代表的なワークフローを 1 つ選び、コード版と declarative 版の差分と運用負荷を比較する。

### リファレンス
- [Move Agent Orchestration/Workflows out of Code with Agent Framework Declarative Workflows 1.0](https://devblogs.microsoft.com/agent-framework/move-agent-orchestration-workflows-out-of-code-with-agent-framework-declarative-workflows-1-0)

## Build locally, ship to Azure: meet Azure SQL Developer

- **Blog:** Azure SQL
- **Author:** Carlos Robles
- **URL:** https://devblogs.microsoft.com/azure-sql/azure-sql-developer-prpr

### 要約
Azure SQL Developer の private preview を紹介しています。Azure SQL Database エンジンをローカルのコンテナーで使えるため、クラウドと同じエンジンで開発・テストし、接続文字列の切り替えだけで本番へ移行できるとしています。

### 開発者にとって重要なこと
Azure SQL を使うアプリ、CI、RAG/AI プロトタイプ、ORM やドライバーの検証を行うチームに関係します。ローカルとクラウドの差分を減らし、内輪の検証や統合テストを安定させやすくなります。

### アクションプラン
- Azure SQL Developer の private preview に登録し、利用条件と制約を確認する。
- ローカル開発や CI でコンテナーを試し、既存の接続文字列・マイグレーション・ORM がそのまま動くか確認する。
- ⚠️ プレビューのレジストリ資格情報は秘密情報として扱い、共有やログ出力を避ける。

### リファレンス
- [Build locally, ship to Azure: meet Azure SQL Developer](https://devblogs.microsoft.com/azure-sql/azure-sql-developer-prpr)

## Smarter Spring Development in Eclipse with GitHub Copilot

- **Blog:** Java
- **Author:** Hang Wang
- **URL:** https://devblogs.microsoft.com/java/smarter-spring-development-in-eclipse-with-github-copilot

### 要約
Eclipse の Spring Tools MCP Server と GitHub Copilot を組み合わせると、Spring プロジェクトのコンテキストをより構造的に扱えることを説明しています。Bean グラフや実行中アプリの情報、Spring 特有の補完や修正を IDE 内で活かす流れです。

### 開発者にとって重要なこと
Eclipse で Spring Boot を開発しているチームに関係します。Copilot がリポジトリ検索以上の文脈を使えるようになれば、ナビゲーション、修正、診断の効率が上がります。

### アクションプラン
- Eclipse + Spring Boot を使っている場合は、Spring Tools MCP Server と GitHub Copilot の組み合わせを評価する。
- Copilot がどの程度プロジェクト文脈を参照できるかを、実際の Bean 定義や実行中アプリで確認する。
- 本文の手順を見て、チーム標準 IDE に採用できるか検討する。

### リファレンス
- [Smarter Spring Development in Eclipse with GitHub Copilot](https://devblogs.microsoft.com/java/smarter-spring-development-in-eclipse-with-github-copilot)
