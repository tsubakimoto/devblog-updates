## Add vs Stage and Register

- **Blog:** Insidemsix
- **Author:** Howard Kapustein
- **URL:** https://devblogs.microsoft.com/insidemsix/add-vs-stage-and-register

### 要約
Windows のパッケージ展開における「ステージング」と「登録」の違いを整理し、`AddPackage*()` が両方をまとめて実行する操作であることを説明しています。単にファイルをディスクへ配置したいのか、ユーザーのプロファイルに登録して利用可能にしたいのかで、使う API を分ける必要があるとしています。

### 開発者にとって重要なこと
MSIX や Windows パッケージを扱う開発者、配布/プロビジョニングの担当者に直接関係します。特に、ユーザー単位の登録が必要か、マシン単位での事前配置だけでよいかで運用設計が変わります。

### アクションプラン
- パッケージ導入フローで、`AddPackage` を使うべきケースと、ステージングと登録を分離すべきケースを整理する。
- 複数ユーザー環境では、登録がユーザー単位である点を前提に配布手順を見直す。
- ⚠️ 既存の配布手順が「インストール = AddPackage 前提」になっている場合、遅延登録や事前ステージングの要件と合っているか確認する。

## Going beyond text in Microsoft 365 Copilot - Introducing SharePoint Copilot Apps

- **Blog:** Microsoft365dev
- **Author:** Vesa Juvonen
- **URL:** https://devblogs.microsoft.com/microsoft365dev/going-beyond-text-in-microsoft-365-copilot-introducing-sharepoint-copilot-apps

### 要約
Microsoft 365 Copilot に、SharePoint Framework (SPFx) ベースのインタラクティブな UX コンポーネントを組み込む「SharePoint Copilot Apps」を紹介しています。テキスト中心のやり取りだけでなく、Copilot canvas 上でその場で操作できる体験を目指しています。

### 開発者にとって重要なこと
Microsoft 365、SharePoint、Teams 周辺の開発者にとって、既存の SPFx 資産を Copilot に再利用できる可能性があります。JavaScript/TypeScript の既存スキルや、AI コーディングエージェントをそのまま活かしやすい点も重要です。

### アクションプラン
- SPFx で構築している既存コンポーネントを、Copilot/SharePoint/Teams で再利用できる候補として棚卸しする。
- 早期 July の preview と SPFx v1.24 の公開タイミングを待ち、tenant の準備やライセンス要件を確認する。
- ⚠️ 企業向けのセキュリティ/ガバナンス要件と、Copilot canvas 上での利用シナリオが合うかを事前に評価する。
