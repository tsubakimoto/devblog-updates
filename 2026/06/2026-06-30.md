## Compose your API surface with Data API builder custom paths

- **Blog:** Azure SQL
- **Author:** Jerry Nixon
- **URL:** https://devblogs.microsoft.com/azure-sql/data-api-builder-custom-rest-paths

### 要約
Data API builder 2.0 の GA とあわせて、REST エンドポイントに compound path を含むカスタムパスを設定できる機能が紹介されています。API の URL 設計をよりドメインに合わせて調整しやすくする更新です。

### 開発者にとって重要なこと
Azure SQL や Data API builder を使って REST API を公開している開発者に関係します。既存のルーティング、クライアント契約、API ゲートウェイ設計に影響する可能性があります。

### アクションプラン
- 現在のエンドポイント設計を見直し、カスタムパスで簡潔化できる箇所がないか検討する。
- 既存クライアントや API ゲートウェイとの互換性を検証する。
- ⚠️ ルート変更がある場合は、移行手順と後方互換性を先に固める。

### リファレンス
- [Compose your API surface with Data API builder custom paths](https://devblogs.microsoft.com/azure-sql/data-api-builder-custom-rest-paths)

## MSIX Per-User vs All Users: Install, Provision, and Uninstall Packages

- **Blog:** Insidemsix
- **Author:** Howard Kapustein
- **URL:** https://devblogs.microsoft.com/insidemsix/msix-per-user-vs-all-users

### 要約
MSIX における per-user と all-users の違い、さらに install / provision / uninstall の関係を整理しています。単純な「インストール」ではなく、登録とプロビジョニングの意味を区別する内容です。

### 開発者にとって重要なこと
Windows アプリの配布、企業向け展開、MSIX の運用に関わる開発者や管理者に直接関係します。複数ユーザー環境での展開設計が、ユーザー単位かマシン単位かで変わります。

### アクションプラン
- 自社の MSIX 展開が per-user か provisioning かを整理する。
- 複数ユーザー端末での登録・削除・再展開の流れを確認する。
- ⚠️ 既存の配布手順が「インストール = 登録」と暗黙に仮定していないか見直す。

## A compatibility note on the abuse of Windows window class extra bytes

- **Blog:** Oldnewthing
- **Author:** Raymond Chen
- **URL:** https://devblogs.microsoft.com/oldnewthing/20260630-00/?p=112488

### 要約
Windows の window class extra bytes を用途外に使う実装に対する互換性上の注意点です。ID がポインタサイズへ拡張された経緯にも触れつつ、古い前提に依存する危険性を示しています。

### 開発者にとって重要なこと
Win32 の低レベル実装や、未文書化の領域に状態を詰め込むコードを持つ開発者に関係します。互換性の前提が崩れると、将来の Windows で予期せぬ不具合につながります。

### アクションプラン
- window class extra bytes をデータ保存に流用している箇所がないか確認する。
- ポインタや識別子の格納先を、文書化された仕組みに置き換える。
- ⚠️ 既存コードが古い互換性前提に依存している場合は、将来の Windows での影響を評価する。

### リファレンス
- [A compatibility note on the abuse of Windows window class extra bytes](https://devblogs.microsoft.com/oldnewthing/20260630-00/?p=112488)
