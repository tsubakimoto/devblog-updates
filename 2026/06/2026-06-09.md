## .NET and .NET Framework June 2026 servicing releases updates

- **Blog:** .NET
- **URL:** https://devblogs.microsoft.com/dotnet/dotnet-and-dotnet-framework-june-2026-servicing-updates

### 要約
.NET と .NET Framework の 2026 年 6 月のサービス更新です。今回の更新にはセキュリティ修正と非セキュリティ修正が含まれています。対象は .NET 10.0 / 9.0 / 8.0 で、複数の CVE が修正されています。リリースノート、インストーラー、コンテナーイメージ、Linux パッケージ、既知の問題の情報も更新されています。運用中の .NET 環境は、パッチ適用とベースイメージ更新を前提に確認が必要です。

### 開発者にとって重要なこと
本番の .NET アプリ、CI/CD のビルド環境、コンテナー運用に直接関係します。特にセキュリティ対応が含まれるため、更新遅れはリスクになります。ランタイムやフレームワークを固定しているチームは影響確認が必要です。

### アクションプラン
- ⚠️ 対象の CVE と自分の実行環境（.NET 10.0 / 9.0 / 8.0）を照合する
- 本番、ステージング、ビルド用イメージを最新の 10.0.9 / 9.0.17 / 8.0.28 に更新する
- Linux パッケージやコンテナーイメージを使っている場合は再ビルドと再デプロイを行う
- 既知の問題を確認して、更新前に回避策が必要か判断する

### リファレンス
- [.NET and .NET Framework June 2026 servicing releases updates](https://devblogs.microsoft.com/dotnet/dotnet-and-dotnet-framework-june-2026-servicing-updates)

## Distributed multi-agent systems with Aspire and Microsoft Agent Framework

- **Blog:** Aspire
- **URL:** https://devblogs.microsoft.com/aspire/distributed-multi-agent-systems-with-aspire-and-microsoft-agent-framework

### 要約
Aspire と Microsoft Agent Framework を使った分散マルチエージェント構成の紹介です。記事では、スキーリゾートのコンシェルジュという現実的なデモを通じて、複数の専門エージェント、ライブデータ、外部ツール、音声/チャット入力、オーケストレーションをどう組み合わせるかを示しています。Microsoft Foundry、A2A、Voice Live なども含めた構成になっています。単一のモデル呼び出しではなく、実運用向けのエージェントアプリに必要な要素をまとめて扱っています。分散システムとしての健康状態や観測性も重要なテーマです。

### 開発者にとって重要なこと
AI エージェントを本番システムとして組み立てるチームに関係します。オーケストレーション、監視、依存サービス、運用設計を含めて考える必要があります。Aspire を使うと、こうした複雑な構成をまとめて扱いやすくなります。

### アクションプラン
- 自分のエージェント構成を「単一アプリ」ではなく「分散サービス群」として整理する
- Aspire のデモ構成を参考に、監視・ヘルスチェック・依存関係の設計を見直す
- ⚠️ 複数エージェントや外部ツール連携を本番化する前に、障害時の切り分け手順を用意する

### リファレンス
- [Distributed multi-agent systems with Aspire and Microsoft Agent Framework](https://devblogs.microsoft.com/aspire/distributed-multi-agent-systems-with-aspire-and-microsoft-agent-framework)

## ICYMI: Inside the Microsoft Agent Framework: How we designed a layered SDK

- **Blog:** Agent Framework
- **URL:** https://devblogs.microsoft.com/agent-framework/icymi-inside-the-microsoft-agent-framework-how-we-designed-a-layered-sdk

### 要約
Microsoft Agent Framework の SDK 設計思想を紹介する記事です。チャット中心の AI 体験から、ツール実行、システム横断の連携、長時間処理まで扱えるアプリへ移る流れを背景にしています。レイヤー化された SDK により、単純な対話だけでなく、複雑なワークフローを扱いやすくする考え方が説明されています。コマンドラインブログでの関連解説への案内も含まれています。MAF を採用する場合の設計判断に役立つ内容です。

### 開発者にとって重要なこと
Agent Framework を使う、または採用を検討している開発者向けです。抽象化の粒度や責務分離をどう設計するかの指針になります。AI 機能を増やしたいチームほど、SDK の層構造を理解しておく価値があります。

### アクションプラン
- Microsoft Agent Framework を使う前提なら、SDK のレイヤー構造を把握して設計に反映する
- ツール呼び出し、RAG、複数ステップ処理の責務分離を自分の実装に当てはめる
- CLI の関連記事も確認して、共通の設計方針をそろえる

## Staging Part 2 - Disk Space Optimization

- **Blog:** Insidemsix
- **URL:** https://devblogs.microsoft.com/insidemsix/staging-part-2-disk-space-optimization

### 要約
MSIX の「disk space optimization」を扱う記事です。MSIX パッケージのファイル共有や、Windows が複数アプリ間でファイルをどう管理するかが説明されています。記事では AppxBlockmap.xml と、ステージング時のファイル展開の仕組みが取り上げられています。MSIX がディスク使用量を抑える理由を、パッケージ構造とインストール処理の観点から整理しています。Windows アプリ配布の内部動作を理解したいチーム向けです。

### 開発者にとって重要なこと
MSIX を使って Windows アプリを配布しているチームに関係します。インストールサイズ、共有ファイル、更新挙動の理解が必要です。パッケージ最適化や配布コストにも影響します。

### アクションプラン
- MSIX のステージングと共有ファイルの仕組みを、現在のパッケージ設計と照らし合わせて確認する
- ⚠️ 更新時のファイル共有や依存関係が、想定どおりに解決されるか検証する
- 配布サイズやインストール時間に課題がある場合は、パッケージ構成を見直す

### リファレンス
- [Staging Part 2 - Disk Space Optimization](https://devblogs.microsoft.com/insidemsix/staging-part-2-disk-space-optimization)

## Copilot Code Reviews for Azure Repos

- **Blog:** DevOps
- **URL:** https://devblogs.microsoft.com/devops/copilot-code-reviews-for-azure-repos

### 要約
Azure Repos 向けに Copilot Code Reviews を提供する記事です。Microsoft は GitHub への移行を推奨しつつも、Azure Repos を使い続ける組織が多い現状を踏まえています。そうしたチームでも、日常の開発フローの中で AI 支援のコードレビューを使えるようにする内容です。Azure DevOps を継続利用している企業向けの実務的な更新です。移行できない制約があっても、レビュー体験を改善できるのがポイントです。

### 開発者にとって重要なこと
Azure Repos を使っているチーム、特に GitHub 移行がまだ難しい組織に関係します。コードレビューの品質向上やレビュー待ち時間の短縮に役立ちます。既存の DevOps 体制を大きく変えずに AI 支援を導入できます。

### アクションプラン
- Azure Repos を使っているか確認し、Copilot Code Reviews の利用可否と提供条件を確認する
- レビュー規約やコンプライアンス要件に照らして、AI レビューの適用範囲を決める
- ⚠️ GitHub への移行計画がある場合は、移行タイミングと Azure Repos 利用継続のバランスを再評価する

### リファレンス

## 🚀React Native Windows v0.83 is here!!

- **Blog:** React Native
- **URL:** https://devblogs.microsoft.com/react-native/react-native-windows-v0-83-is-here

### 要約
React Native Windows 0.83.0 のリリース案内です。React Native 0.83.4 と揃えた更新で、Fabric アーキテクチャの拡充が中心になっています。入力イベントや自動化の対応範囲が広がり、XAML islands のアクセシビリティも改善されています。さらに、コンポーネント性能を計測・保護するための新しいテスト基盤が追加されています。Windows 向け React Native アプリの安定性、性能、保守性を強化する更新です。

### 開発者にとって重要なこと
React Native Windows で Windows アプリを開発しているチームに直接関係します。Fabric への移行状況、入力イベント、アクセシビリティ、CI での性能検証に影響します。アップグレード時の検証項目が増える可能性があります。

### アクションプラン
- ⚠️ 既存アプリの RNW 0.83 へのアップグレード影響を、Fabric・入力・アクセシビリティの観点で確認する
- 新しいパフォーマンステスト基盤を CI に組み込み、回帰検出に使う
- ポインターイベントや XAML islands を使う UI は、実機で再検証する

### リファレンス
- [🚀React Native Windows v0.83 is here!!](https://devblogs.microsoft.com/react-native/react-native-windows-v0-83-is-here)
