## Enterprise Live Migrations is now in public preview

- **Blog:** DevOps
- **Author:** Soo Stahl
- **URL:** https://devblogs.microsoft.com/devops/enterprise-live-migrations-public-preview

### 要約
Azure Repos のリポジトリを GitHub Enterprise Cloud へ、データ所在を保ちながら移行するための Enterprise Live Migrations が public preview になりました。大規模な企業移行で起こりがちな中断を抑えつつ、Azure DevOps から GitHub への移行を支援する内容です。

### 開発者にとって重要なこと
Azure DevOps を使っている組織、特に GitHub Enterprise Cloud への移行を計画しているチームに関係します。移行時の運用停止やデータ所在要件を気にする管理者、プラットフォーム担当、開発基盤チームは詳細を確認する価値があります。

### アクションプラン
- Azure DevOps から GitHub Enterprise Cloud への移行計画がある場合は、この preview の要件と制約を確認する。
- データ所在、移行対象リポジトリ、切り替え手順が自組織のコンプライアンス要件に合うかを検証する。
- ⚠️ 本番移行の前に、代表的なリポジトリで試験移行を行い、開発フローへの影響を洗い出す。

### リファレンス
- [Enterprise Live Migrations is now in public preview](https://devblogs.microsoft.com/devops/enterprise-live-migrations-public-preview)

## Power Azure SRE Agent with the tools it needs

- **Blog:** Azure Sdk
- **Author:** Lily Ma
- **URL:** https://devblogs.microsoft.com/azure-sdk/power-azure-sre-agent-with-connector-namespace

### 要約
Azure SRE Agent の機能を、Azure Connector Namespace 上でホストされた MCP サーバーに接続することで拡張する方法を紹介しています。Connector Namespace は MCP サーバーの self-hosting に伴う運用・管理負担を下げる managed hosting platform と説明されています。

### 開発者にとって重要なこと
Azure 上で SRE エージェントや MCP ベースのツール連携を使うチームに関係します。運用自動化やエージェント拡張を進めている場合、どのツールをどこでホストするかの選択肢に影響します。

### アクションプラン
- Azure SRE Agent と MCP サーバー連携を使っている場合は、Connector Namespace の利用可否を確認する。
- self-hosting の運用負荷と managed hosting のトレードオフを比較する。
- 既存の MCP サーバー構成を見直し、必要な権限・接続先・監査要件を整理する。

### リファレンス
- [Power Azure SRE Agent with the tools it needs](https://devblogs.microsoft.com/azure-sdk/power-azure-sre-agent-with-connector-namespace)

## Bacpac and Dacpac, the similarities and differences

- **Blog:** Azure SQL
- **Author:** Drew Skwiers-Koballa
- **URL:** https://devblogs.microsoft.com/azure-sql/bacpac-and-dacpac-the-similarities-and-differences

### 要約
Bacpac と Dacpac という 2 種類のパッケージの共通点と違いを整理する記事です。SqlPackage や他の SQL ツールでデータベース全体やオブジェクトを移動する際に、どちらを使うかの判断材料を提供しています。

### 開発者にとって重要なこと
SQL Server / Azure SQL を扱う開発者、DBA、リリース担当に関係します。バックアップ、移行、スキーマ配布、環境差分の扱いを誤るとデプロイや復旧に影響するため、用途の違いを理解することが重要です。

### アクションプラン
- データ移行とスキーマ配布のどちらが目的かを明確にし、bacpac / dacpac の使い分けを確認する。
- SqlPackage や運用スクリプトで両者を使っている場合は、現在の手順が目的に合っているか見直す。
- 詳細が必要なら本文を参照し、チームの DB 運用ガイドに反映する。

### リファレンス
- [Bacpac and Dacpac, the similarities and differences](https://devblogs.microsoft.com/azure-sql/bacpac-and-dacpac-the-similarities-and-differences)

## AWE does not require PAE, though PAE makes it much more useful

- **Blog:** Oldnewthing
- **Author:** Raymond Chen
- **URL:** https://devblogs.microsoft.com/oldnewthing/20260831-00/?p=112660

### 要約
Windows の Address Windowing Extensions (AWE) と、x86-32 の Physical Address Extension (PAE) の関係を解説しています。AWE は PAE なしでも使えるが、PAE があるとより有用になる、という点を扱っています。

### 開発者にとって重要なこと
低レベルの Windows 開発、メモリ管理、古い 32-bit 環境を扱うソフトウェアに関係します。一般的なアプリ開発よりも、システム寄りの実装や互換性検証を行うチームに有用です。

### アクションプラン
- 32-bit Windows やメモリ常駐・大容量メモリを扱うコードがある場合は、AWE/PAE の前提を確認する。
- 古いプラットフォーム向けの実装やドキュメントがあるなら、現在の前提と整合しているか見直す。
- 詳細な挙動は本文参照とし、互換性判断は実機または対象環境で検証する。

### リファレンス
- [AWE does not require PAE, though PAE makes it much more useful](https://devblogs.microsoft.com/oldnewthing/20260831-00/?p=112660)
