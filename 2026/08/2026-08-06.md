## Test reporting in Microsoft.Testing.Platform: from red build to root cause

- **Blog:** .NET
- **Author:** Amaury Levé
- **URL:** https://devblogs.microsoft.com/dotnet/microsoft-testing-platform-reporting

### 要約
CI でテストが失敗したときに、単に「赤いビルド」として見るだけでなく、変更起因かどうか、過去にも失敗しているか、根拠はどこにあるかを追えるテスト報告の話です。投稿の主眼は、失敗原因の特定をログ探索や手作業に頼らず進められるようにする点にあります。

### 開発者にとって重要なこと
.NET のテスト実行や CI を使うチームに関係します。失敗の切り分け時間を減らし、再現性や履歴確認をしやすくすることで、レビューや修正の速度に影響します。

### アクションプラン
- .NET の CI で Microsoft.Testing.Platform を使っている場合、テスト失敗時にどこまで原因追跡できるか確認する
- チームの失敗対応フローで、ログ・成果物・履歴のどれを見るべきかを整理する
- 詳細は本文参照

## Pull request annotations on work item cards

## You can now use the Azure DevOps Service Connection instead of a PAT or Build Session token

- **Blog:** DevOps
- **Author:** Eric van Wijk
- **URL:** https://devblogs.microsoft.com/devops/you-can-now-use-the-azure-devops-service-connection-instead-of-a-pat-or-build-session-token

### 要約
Azure DevOps へのアクセスに、PAT や session token の代わりに Azure DevOps service connection を使えるようになったという発表です。Microsoft Entra workload identity を使う新しい認証方法として紹介されています。

### 開発者にとって重要なこと
CI/CD パイプラインで Azure DevOps を利用するチーム、特に秘密情報の管理を見直したい組織に重要です。PAT 依存を減らし、より管理しやすい認証構成へ移行する判断材料になります。

### アクションプラン
- ⚠️ Azure DevOps の認証で PAT を使っているパイプラインがあれば、service connection へ置き換え可能か確認する
- Entra workload identity ベースの設定手順と権限モデルを確認する
- 秘密情報ローテーションや運用負荷への影響を評価する

### リファレンス
- [You can now use the Azure DevOps Service Connection instead of a PAT or Build Session token](https://devblogs.microsoft.com/devops/you-can-now-use-the-azure-devops-service-connection-instead-of-a-pat-or-build-session-token)
