## Only believe what you can validate: a verification framework for agentic AI

- **Blog:** All Things Azure
- **Author:** jkordick
- **URL:** https://devblogs.microsoft.com/all-things-azure/only-believe-what-you-can-validate

### 要約
エージェント型 AI に対しては「信じる前に検証する」姿勢が重要だという観点から、検証フレームワークを紹介しています。前回のモダン化と agentic AI に関する記事を踏まえ、今回は特に validation に焦点を当てています。

### 開発者にとって重要なこと
Azure 上で AI を組み込むチーム、特に modernization や agentic AI の導入を進める開発者に関係します。AI の出力や自動化の結果をそのまま採用せず、評価・検証・ガードレールを設計に組み込む必要があります。

### アクションプラン
- Azure で agentic AI を使っているチームは、生成結果の検証ポイントをワークフローに明示的に追加する。
- モダナイゼーションや自動化の各ステップで、どの結果を機械的に受け入れずに確認すべきか整理する。
- 詳細は本文を参照し、既存の評価基準や運用ルールに合うか確認する。

### リファレンス

## Try the new SqlClient and Retry connections natively

- **Blog:** Azure SQL
- **Author:** Jerry Nixon
- **URL:** https://devblogs.microsoft.com/azure-sql/sqlclient-retry

### 要約
.NET の SqlClient と SQL Server 接続に関する更新を案内する投稿です。新しい SqlClient と、接続リトライをネイティブに扱う機能を試せることが中心で、既存の ADO.NET / System.Data.SqlClient の流れを踏まえた改善として紹介されています。

### 開発者にとって重要なこと
Azure SQL や SQL Server に接続する .NET アプリケーション、特に業務アプリや常時接続に近いワークロードに関係します。接続の安定性やエラー耐性を見直したいチームは、ドライバー更新とリトライ戦略の影響を確認する必要があります。

### アクションプラン
- Azure SQL / SQL Server を使う .NET アプリで、現在の SqlClient のバージョンと接続設定を確認する。
- 接続失敗時の再試行がアプリ側でどのように実装されているかを棚卸しし、ネイティブ機能への移行可否を検討する。
- ⚠️ 更新時は、接続文字列、再試行ポリシー、既存のタイムアウト設定との相互作用を検証する。
- 詳細は本文を参照し、運用中ワークロードへの適用範囲を判断する。

### リファレンス
- [Try the new SqlClient and Retry connections natively](https://devblogs.microsoft.com/azure-sql/sqlclient-retry)
