## Visual Studio Code CMake Tools 1.24

- **Blog:** Cppblog
- **Author:** Hannia Valera
- **URL:** https://devblogs.microsoft.com/cppblog/visual-studio-code-cmake-tools-1-24

### 要約
CMake Tools 1.24 では、エディターから CTest のテストを実行・デバッグできる CodeLens、プリセット由来のキャッシュ編集を `CMakeUserPresets.json` の上書きとして保存する機能、ソースファイルの追加・削除に応じて `CMakeLists.txt` を更新する支援機能が追加されました。信頼性と開発効率を高める更新ですが、`CMakeLists.txt` の自動編集は対応する構成に限られ、一般的な CMake スクリプトの書き換え機能ではありません。

### 開発者にとって重要なこと
CMake と VS Code で C++ プロジェクトを開発するチームが対象です。テスト対象だけをビルドして実行する反復が短縮され、共有プリセットを変更せずに個人・環境固有のキャッシュ設定を保持できるため、チーム設定とローカル設定を分離しやすくなります。

### アクションプラン
- CMake Tools を更新し、CTest の CodeLens から対象テストをビルド・実行・デバッグできることを確認する。
- プリセット由来のキャッシュ値を変更するプロジェクトでは、Cache Editor の `Source` 表示と `CMakeUserPresets.json` への上書き結果をレビューする。
- ソースファイルの追加・削除を行う場合は、`cmake.modifyLists.*` の設定と確認動作を確認し、自動更新後のターゲット・変数・生成スクリプトを必ずレビューする。
- 利用中の C/C++ 拡張、デバッガー、テスト構成とリリースノートの変更点をチームの開発環境で検証する。

## WinAppCLI v0.7.0 - Windows Sandbox automation, Native AOT support, single-file applications, and more

- **Blog:** Ifdef Windows
- **Author:** Zachary Teutsch
- **URL:** https://devblogs.microsoft.com/ifdef-windows/winappcli-v0-7-0-release-announcement

### 要約
Windows App Development CLI v0.7.0 では、Windows Sandbox 内での実行・デバッグ・UI オートメーション、Native AOT アプリのパッケージ ID 付き実行、.NET プロジェクトのワンステップパッケージング、パッケージ ID を持つ単一 `.cs` ファイルの実行が導入されました。さらに、参照 API の検索、純粋な C# による Reactor（MVU）テンプレート、スコープ付き・型付き UI オートメーション、再利用可能な NuGet パッケージが提供されます。

### 開発者にとって重要なこと
WinUI/Windows App SDK アプリの開発、テスト、自動化を行う個人・チームが対象です。`--on sandbox` によりホストへアプリをインストールせずに、ゲスト内のデプロイ、実行、検査、操作を反復できます。`find-api --json` や型付き UI クエリは、AI コーディングエージェントや並列 UI 操作の再現性向上にも関係します。

### アクションプラン
- `winget install Microsoft.WinAppCLI` などで v0.7.0 を導入し、既存の Windows App プロジェクトで `winapp run`、`winapp pack`、UI 操作の互換性を確認する。
- ⚠️ Sandbox 実行を試す場合は、Windows Sandbox の前提条件、ゲストへのランタイム供給、`winapp target` の push/pull、キャプチャ保存先を検証する。Sandbox を要求したコマンドがホストへフォールバックしない点もテストする。
- Native AOT、ARM64、単一ファイル実行を採用する場合は、パッケージ ID、ランタイム API、発行設定、署名・配布フローを検証する。
- Reactor テンプレートは実験的で prerelease パッケージと .NET 10 以降を必要とするため、本番の標準テンプレートにする前に API の変更可能性とビルド環境を確認する。
- `find-api` とスコープ付き UI セレクターを自動化に組み込む場合は、復元済み API インデックス、終了コード、`WINAPP_UI_WORKFLOW_ID` による同時実行単位を CI で確認する。

## AG-UI Protocol now has a first-class .NET SDK

- **Blog:** .NET
- **Author:** Daniel Roth
- **URL:** https://devblogs.microsoft.com/dotnet/ag-ui-dotnet-sdk

### 要約
Microsoft と CopilotKit が AG-UI（Agent-User Interaction Protocol）の .NET SDK を提供し、C# のサービスが標準化されたイベントストリームでエージェントとユーザー向けアプリケーションを接続できるようになりました。NuGet の `AGUI.Server` はエージェントを AG-UI エンドポイントとして公開し、`AGUI.Client` は他言語を含む AG-UI エージェントを .NET アプリから利用できます。Microsoft Agent Framework の .NET AG-UI サポートもこの SDK を基盤にしています。

### 開発者にとって重要なこと
トークンのストリーミング、ツール呼び出し、状態更新、割り込み、推論などを UI に表示するエージェントを .NET で構築するチームに関係します。`IChatClient` と共通のプリミティブを使えるため、C# のバックエンドを React/CopilotKit、.NET、Python、TypeScript などのクライアントと接続しやすくなりますが、HTTP サーバー、認証、認可、セッション所有権はアプリケーション側で管理します。

### アクションプラン
- `AGUI.Server` と `AGUI.Client` の最小サンプルを動かし、Server-Sent Events の接続、`RUN_STARTED`/`RUN_FINISHED`、テキスト・ツール・状態イベントの処理を確認する。
- 既存の `IChatClient` または Microsoft Agent Framework エージェントを接続し、React/CopilotKit など実際の UI でストリーミング、承認、割り込み、エラー表示を評価する。
- 認証済みユーザーと会話・スレッドを対応付け、エンドポイントの認証・認可、状態の保持・削除、長時間実行のキャンセルを実装・テストする。
- プロトコルのイベント互換性、NuGet パッケージのバージョン、テレメトリ、マルチモーダルや並列ツール呼び出しなど必要なサンプルを確認してから本番導入を判断する。

### リファレンス

## Debugging walkthrough: Access violation on nonsense instruction, episode 3

- **Blog:** Oldnewthing
- **Author:** Raymond Chen
- **URL:** https://devblogs.microsoft.com/oldnewthing/20260925-00/?p=112731

### 要約
複数の無関係な 32 ビットプロセスで「メモリを書き込めない」アクセス違反が発生した事例を、クラッシュダンプと逆アセンブルから追跡しています。ゼロバイトを命令として実行していたコードは、64 ビット用の detour（絶対アドレスをレジスタに読み込んでジャンプする処理）を 32 ビットプロセスへ注入したもので、原因は利用していたマルウェア対策ソフトの互換性問題でした。

### 開発者にとって重要なこと
ネイティブコード、API フック、セキュリティ製品、クラッシュダンプを扱う開発・サポートチームに関係します。命令ポインター、プロセスのビット数、実行可能メモリ、注入元 DLL を確認すれば、アプリ固有のバグではなく外部の detour/injection が原因であることを切り分けられます。

### アクションプラン
- アクセス違反のダンプでは、命令ポインター付近を逆アセンブルし、命令バイト、プロセスの x86/x64、レジスタ、メモリ保護属性を併せて確認する。
- 実行可能な匿名メモリや不自然な detour を見つけた場合は、`!address`、文字列、ロード済みモジュール、セキュリティ製品の DLL との関係を調査する。
- 32 ビット・64 ビット双方のプロセスでフック製品や EDR/マルウェア対策ソフトの互換性を検証し、ベンダーの更新版と既知の問題を確認する。
- ⚠️ セキュリティ製品を無効化して恒久運用せず、影響範囲を限定した検証環境で原因を確認したうえで、ベンダーへのエスカレーションと社内承認済みの更新を進める。
