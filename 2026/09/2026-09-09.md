## What’s new in Microsoft Foundry: July and August 2026

- **Blog:** Foundry
- **Author:** Nick Brady
- **URL:** https://devblogs.microsoft.com/foundry/whats-new-in-microsoft-foundry-july-august-2026

### 要約
Microsoft Foundry の 2026 年 7 月〜8 月の更新をまとめた記事です。Hosted Agents、Voice Live integration、Toolboxes の一般提供に加え、Azure 上でホストされる Claude tools の拡張、Model Router のリージョンとモデルプールの更新、Foundry Local の機能強化、Python / JavaScript / Java / .NET SDK の前進が案内されています。

### 開発者にとって重要なこと
AI エージェントや Foundry ベースのアプリケーションを扱うチームに関係します。モデル選定、エージェント実行基盤、ローカル/クラウドの開発体験、各言語 SDK の追従状況に影響します。

### アクションプラン
- Foundry を使っているプロジェクトで、Hosted Agents や Toolboxes の利用可否を確認する
- ⚠️ Model Router や対応リージョンの変更が本番構成に影響しないか見直す
- Python / JavaScript / Java / .NET SDK の更新内容を確認し、依存更新計画に反映する

### リファレンス

## Advancing trusted AI innovation with Agents and new Azure OpenAI models in Azure Government

- **Blog:** Azuregov
- **Author:** Douglas Phillips
- **URL:** https://devblogs.microsoft.com/azuregov/advancing-ai-innovation-in-azure-government

### 要約
Azure Government 向けの AI 機能拡張が発表されています。Microsoft Foundry Agent Service が Azure Government で利用可能になり、認可済み情報を扱い、承認済みツールを使い、複数ステップの作業を進めるための管理基盤が提供されます。あわせて新しい Azure OpenAI モデルの提供も案内されています。

### 開発者にとって重要なこと
米国政府向けの Azure 環境で AI を構築・運用するチームに直接関係します。データ境界、認可、運用統制を保ちながらエージェント型ワークロードを導入する際の選択肢が広がります。

### アクションプラン
- Azure Government で AI ワークロードを計画しているなら、Foundry Agent Service の適用可否を確認する
- ⚠️ 承認済み情報・承認済みツールのみで完結する設計になっているか見直す
- 利用可能になった Azure OpenAI モデルを要件・コンプライアンスと照らして評価する

### リファレンス
- [Advancing trusted AI innovation with Agents and new Azure OpenAI models in Azure Government](https://devblogs.microsoft.com/azuregov/advancing-ai-innovation-in-azure-government)

## Your work might not need the smartest model

- **Blog:** Blog
- **Author:** Waldek Mastykarz
- **URL:** https://devblogs.microsoft.com/blog/your-work-might-not-need-the-smartest-model

### 要約
すべての作業に最も高性能なモデルを使う必要はない、という観点を扱う記事です。最適なモデル選択は、品質だけでなくコストとのバランスで判断すべきだと述べています。

### 開発者にとって重要なこと
AI を開発フローや製品に組み込むチームに関係します。既定モデルの選び方、コスト管理、用途ごとのモデル切り替え方針を見直すきっかけになります。

### アクションプラン
- 自分たちのワークロードで、最上位モデルが本当に必要な場面を整理する
- ⚠️ 速度・品質・コストのトレードオフを前提に、用途別のモデル選定基準を作る
- 既定モデルを固定している場合は、実利用の精度とコストを比較して見直す

### リファレンス
- [Your work might not need the smartest model](https://devblogs.microsoft.com/blog/your-work-might-not-need-the-smartest-model)
