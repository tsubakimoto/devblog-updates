## Aspire 13.6: Your dashboard gets memory

- **Blog:** Aspire
- **Author:** Maddy Montaquila
- **URL:** https://devblogs.microsoft.com/aspire/whats-new-aspire-13-6

### 要約
Aspire 13.6 では、Aspire Dashboard が実行履歴を保持する永続的なダッシュボードデータに対応しました。フルスタックを再起動した後も、過去の実行のトレースやログを確認できます。

### 開発者にとって重要なこと
Aspire で分散アプリケーションを開発・デバッグするチームは、再起動で失われていた観測データを後から確認できるようになります。障害調査やローカル開発で、再現直後にログを保存する負担を減らせます。

### アクションプラン
- Aspire 13.6 に更新し、Dashboard の永続データ保存先と保持期間を開発環境で確認する。
- 再起動後のトレース・ログ参照を試し、既存のログ収集や障害調査手順との重複を整理する。
- チームで共有する環境では、保存データの容量、アクセス制御、不要データの削除方針を確認する。

### リファレンス

## Why content extraction still matters in the GenAI era

- **Blog:** Foundry
- **Author:** Chu Lahlou
- **URL:** https://devblogs.microsoft.com/foundry/why-content-extraction-still-matters-in-the-genai-era

### 要約
企業向け AI の信頼性は、選択したモデルだけでなく、エージェントが処理するコンテンツをどれだけ正確に抽出できるかに左右されるという考えを解説しています。大規模言語モデルの時代でも、信頼できる入力データを準備するコンテンツ抽出が重要だとしています。

### 開発者にとって重要なこと
文書を検索・要約・判断に利用する AI システムでは、抽出漏れや構造の破壊がそのまま回答品質と業務上の判断に影響します。モデルの比較だけでなく、取り込み、構造化、検証のパイプラインを設計するチームに関係します。

### アクションプラン
- Foundry を使う AI パイプラインで、PDF や表など入力形式ごとの抽出品質を評価するテストデータを用意する。
- 抽出結果の出典、構造、欠落を検証し、モデルに渡す前の品質ゲートを設ける。
- 詳細な手法や利用可能なサービスは本文を確認し、モデル性能の改善だけで解決しない失敗要因を洗い出す。

### リファレンス

## Build with Azure Canvases: a shared workspace for agents

- **Blog:** Blog
- **Author:** Matt Hernandez
- **URL:** https://devblogs.microsoft.com/blog/azure-canvases

### 要約
GitHub Copilot 向け Azure canvases は、Copilot との会話に隣接した対話型ワークスペースです。Azure リソースの参照、コストデータの調査、アクションの誘導など、発見・分析・実行の作業をチャットの外側でも進められます。

### アクションプラン
- Azure canvases を利用できる環境で、リソース探索、コスト分析、変更提案の流れを小さな検証作業で試す。
- 実行権限を持つ操作では、Copilot の提案内容、対象リソース、差分、承認手順を人が確認する運用にする。
- チーム利用時は、共有情報に含まれる機密データ、アクセス権、監査要件を確認する。

### リファレンス

- チーム標準を変更する場合は、開発者向けセットアップ手順とトラブルシューティングを更新する。

## DiskANN Vector Index and Vector Search Are Now Generally Available in Azure SQL

- **Blog:** Azure SQL
- **Author:** Pooja Kamath
- **URL:** https://devblogs.microsoft.com/azure-sql/diskann-vector-index-search-are-now-generally-available-in-azure-sql

### 要約
DiskANN ベクトルインデックスとベクトル検索が、Azure SQL Database、常に最新の更新ポリシーを使用する Azure SQL Managed Instance、Microsoft Fabric の SQL database で一般提供になりました。SQL エンジン内でスケーラブルな近似最近傍検索を行い、リレーショナルデータとベクトルを組み合わせられます。

### 開発者にとって重要なこと
ベクトル検索用の別システムを追加せず、既存の SQL データとベクトル検索を同じ基盤で扱う構成を検討できます。RAG やセマンティック検索では、検索性能、インデックス設計、トランザクションデータとの整合性を含めて評価する必要があります。

### アクションプラン
- Azure SQL または Fabric の対象環境で DiskANN の可用性、リージョン、料金、対応するベクトル型を確認する。
- 実データに近いベクトルとクエリで、検索精度、レイテンシー、インデックス作成・更新コストを測定する。
- 既存のベクトルストアから移行する場合は、再インデックス、バックアップ、ロールバック、SQL 権限を含む移行計画を作る。

### リファレンス
