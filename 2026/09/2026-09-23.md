## Microsoft is updating its author-signing certificate starting September 23, 2026

- **Blog:** .NET
- **Author:** The NuGet Team
- **URL:** https://devblogs.microsoft.com/dotnet/microsoft-author-signing-certificate-update-2026

### 要約
Microsoft が NuGet パッケージの著者署名に使用する X.509 証明書を、2026 年 9 月 23 日から新しい証明書へ切り替えます。既存パッケージの署名は維持されますが、Microsoft の署名者を NuGet クライアントポリシーの許可リストで検証している環境や、`dotnet nuget verify` で証明書フィンガープリントを指定している環境では、新しい証明書の追加が必要です。

### 開発者にとって重要なこと
署名検証を必須にしている開発環境、CI/CD、社内 NuGet プロキシでは、許可リストが更新されていないと新しく署名された Microsoft パッケージのインストールや検証に失敗する可能性があります。通常の NuGet 利用で署名者を明示的に制限していない環境は影響を受けない見込みです。

### アクションプラン
- ⚠️ リポジトリ、開発端末、ビルドエージェントにあるすべての `nuget.config` の `trustedSigners` を確認し、Microsoft の新しい SHA-256 フィンガープリント `9A1B131BEE0605433056A4EA3815478A8E177961A968C6C0027C1093D1FEB630` を追加する。
- `dotnet nuget verify` の利用箇所を検索し、新しいフィンガープリントを既存の値を残したまま追加する。
- CI で Microsoft の NuGet パッケージを取得・検証し、移行後も旧証明書で署名された既存パッケージを検証できることを確認する。

- [Microsoft is updating its author-signing certificate starting September 23, 2026](https://devblogs.microsoft.com/dotnet/microsoft-author-signing-certificate-update-2026)

## When working with Win32 FILETIME, don't forget that you have std::chrono now

- **Blog:** The Old New Thing
- **Author:** Raymond Chen
- **URL:** https://devblogs.microsoft.com/oldnewthing/20260923-00/?p=112726

### 要約
Win32 の `FILETIME` を使って経過時間を手計算する代わりに、既存のヘルパーや C++ の `std::chrono` を利用する方法を紹介しています。C++/WinRT の時計変換と時間リテラルを使えば、単位変換用の定数や低レベルな整数計算をコードに持ち込まずに済みます。

### 開発者にとって重要なこと
Win32 API と C++ を組み合わせるコードで、時刻差分の計算ミスや可読性の低下を減らせます。ファイル時刻やシステム時刻を扱う既存のネイティブコードを保守するチームに特に関係します。

### アクションプラン
- `FILETIME` の DWORD 分割、100 ナノ秒単位、秒・分の定数を手計算している箇所を検索する。
- C++/WinRT の `winrt::clock::from_FILETIME` と `std::chrono` の期間・リテラルで置き換えられるか検討する。
- 過去時刻・未来時刻・オーバーフローを含む既存テストを実行し、置換後の丸めと境界動作を確認する。

### リファレンス
- [When working with Win32 FILETIME, don't forget that you have std::chrono now](https://devblogs.microsoft.com/oldnewthing/20260923-00/?p=112726)
