## Get started with the GitHub Copilot app: a free, hands-on course

### 要約

## Build Agentic UI with the new Blazor AI components

- **Blog:** .NET
- **Author:** Daniel Roth
- **URL:** https://devblogs.microsoft.com/dotnet/build-agentic-ui-blazor

### 要約
実験的な Blazor AI components が、ストリーミングされるエージェント応答、ツール呼び出し、承認、フロントエンド操作を、Blazor が描画・制御できる `ContentBlock` として扱うための部品と状態モデルを提供します。`ChatPage` から始められるほか、`AgentBoundary`、`MessageList`、`MessageInput`、`BlockRenderer<TBlock>` でカスタム UI を構築でき、Microsoft.Extensions.AI、AG-UI .NET SDK、Microsoft Agent Framework、ASP.NET Core、Microsoft Foundry、Aspire と連携します。

### 開発者にとって重要なこと

### アクションプラン
- ⚠️ 実験的パッケージであることを踏まえ、.NET 11 RC1 と `Microsoft.AspNetCore.Components.AI --prerelease` を隔離した検証プロジェクトで試す。
- AgenticUI サンプルを動かし、ストリーミング、ツール呼び出し、承認、共有状態を自分の UI 要件に照らして評価する。
- リモートエージェントを使う場合は AG-UI のイベント、HTTP/SSE 接続、認可、エラー時の再試行と中断を設計・検証する。
- モデル出力やツール実行の結果をユーザーが確認できる表示と、影響の大きい操作に対する承認フローを用意する。

## SQLAlchemy 2.1 brings built-in support for mssql-python

- **Blog:** Azure SQL
- **Author:** Matt Hyon
- **URL:** https://devblogs.microsoft.com/azure-sql/sqlalchemy-2-1-brings-built-in-support-for-mssql-python

### 要約
SQLAlchemy 2.1.0 が一般提供され、Microsoft の SQL Server 向け Python ドライバー `mssql-python` を、公式の `mssql+mssqlpython` dialect として ORM および Core API から利用できるようになりました。外部 ODBC ドライバーの別途導入を減らしつつ、Microsoft Entra 認証や managed identity に対応し、既存の SQLAlchemy のモデル、セッション、トランザクション、Alembic の運用を維持できます。

### 開発者にとって重要なこと
SQL Server/Azure SQL を Python から利用するチームは、ドライバーのインストールとデプロイを簡素化できる可能性があります。SQLAlchemy 2.1 は Python 3.11 以降が必要で、`mssql+pyodbc` から移行する場合は接続 URL と依存関係の変更に加えて、クエリ、トランザクション、接続プール、マイグレーションの互換性確認が必要です。

### アクションプラン
- Python の実行環境が 3.11 以降か確認し、検証環境で `python -m pip install "SQLAlchemy[mssql-python]>=2.1.0"` を試す。
- 既存の `mssql+pyodbc` アプリは、接続 URL を変更した場合の認証、暗号化、クエリ、トランザクション、接続プールを回帰テストする。
- Azure 上の本番ワークロードでは、保存パスワードを減らせる Microsoft Entra managed identity の適用可否を検討する。
- SQLAlchemy 2.1 の移行ガイドを確認し、依存関係をポリシーに従って固定してから段階的に展開する。

### リファレンス
- [SQLAlchemy 2.1 brings built-in support for mssql-python](https://devblogs.microsoft.com/azure-sql/sqlalchemy-2-1-brings-built-in-support-for-mssql-python)

## Announcing the Public Preview of Local Time Zone Support in Azure SQL Database

- **Blog:** Azure SQL
- **Author:** Umachandar Jayachandran (UC)
- **URL:** https://devblogs.microsoft.com/azure-sql/announcing-the-public-preview-of-local-time-zone-support-in-azure-sql-database

### 要約
Azure SQL Database で、データベース単位の永続設定とセッション単位の一時的な上書きによるローカルタイムゾーン指定が Public Preview になりました。`ALTER DATABASE SCOPED CONFIGURATION SET TIME_ZONE` と ANSI SQL の `SET TIME ZONE` を使い、`GETDATE()`、`CURRENT_DATE`、`SYSDATETIMEOFFSET()` などの現在日時関数を有効なタイムゾーンに応じて返せます。

### 開発者にとって重要なこと
マルチリージョン SaaS や、異なるタイムゾーンのオンプレミス SQL Server を集約する構成で、データベースごとのローカル時刻をアプリケーション側の変換だけに頼らず扱えます。設定は過去に保存した日時を変換せず、`AT TIME ZONE` は従来どおり明示したタイムゾーンで独立して動作するため、`datetime2` と `datetimeoffset` の使い分けも変わりません。

### アクションプラン
- ⚠️ Public Preview のため、本番の時刻基盤を直ちに切り替えず、サポート対象リージョンと制限を確認して検証環境で評価する。
- `sys.time_zone_info` で利用可能な Windows タイムゾーン識別子を確認し、データベース設定とセッション設定の優先順位をテストする。
- 現在日時関数に依存するジョブ、監査、請求、日付境界の処理を、DST を含む複数地域で回帰テストする。
- 保存値の意味を棚卸しし、瞬間を保持する列には `datetimeoffset` や UTC 保存を検討し、既存データの変換が自動で行われないことをチームに周知する。

- [Announcing the Public Preview of Local Time Zone Support in Azure SQL Database](https://devblogs.microsoft.com/azure-sql/announcing-the-public-preview-of-local-time-zone-support-in-azure-sql-database)

## C++ reminder: Function-local static variables are initialized only once, even if it looks like they get initialized multiple times

- **Blog:** Oldnewthing
- **Author:** Raymond Chen
- **URL:** https://devblogs.microsoft.com/oldnewthing/20260928-00/?p=112738

### 要約
関数ローカルの `static` 変数は、宣言に初めて実行が到達した時に一度だけ初期化され、その後の呼び出しでは同じ値を保持します。参照メンバーがローカル変数を参照してしまう use-after-free を避けるために `static` 化する例を題材に、複数インスタンスで値を共有する問題、呼び出しごとの代入による競合、スレッドデータ競合を説明しています。

### 開発者にとって重要なこと
`static` は寿命を延ばしますが、インスタンスごとの状態を保持する仕組みにはなりません。寿命を共有すべきオブジェクトとコントローラーを aliasing `shared_ptr` で管理する方法も示されますが、根本的には参照ではなく必要な情報を値としてコピーする設計が、所有権と並行性を明確にします。

### アクションプラン
- 関数ローカル `static` にインスタンス固有の設定やリクエスト値を保存していないか、コードレビューと静的解析で確認する。
- コールバックやコントローラーがローカルデータを参照保持していないか確認し、所有権を共有するか値をコピーする設計へ見直す。
- `static` の共有状態を呼び出しごとに書き換えるコードは、重複ライフタイムと並行呼び出しのテストを追加し、必要なら mutex など適切な同期を行う。

### リファレンス
- [C++ reminder: Function-local static variables are initialized only once, even if it looks like they get initialized multiple times](https://devblogs.microsoft.com/oldnewthing/20260928-00/?p=112738)
