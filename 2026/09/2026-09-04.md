## What happens if you change a window class's GCL_ CBWNDEXTRA ?

- **Blog:** Oldnewthing
- **Author:** Raymond Chen
- **URL:** https://devblogs.microsoft.com/oldnewthing/20260904-00/?p=112675

### 要約
Windows のウィンドウクラスにある extra bytes の扱いを、設定を変更した場合どうなるかという観点で扱う記事です。システム内部の挙動や、過去の仕様変遷を踏まえた技術的な解説だと読み取れます。

### 開発者にとって重要なこと
Win32 や UI 基盤を扱う開発者、特に低レベルのウィンドウクラス設定に依存するコードを持つチームに関係します。内部実装や古い前提に依存したコードの移植性・保守性を見直す材料になります。

### アクションプラン
- Win32 のウィンドウクラス設定で extra bytes を使っている箇所があるか確認する
- 古い Windows 前提のコードが、現在の挙動でも安全か見直す
- 詳細な影響範囲は本文を参照し、必要なら実機で再現確認する

## Native memory for Microsoft Agent Framework with Azure Cosmos DB

- **Blog:** Agent Framework
- **Author:** Wes Steyn
- **URL:** https://devblogs.microsoft.com/agent-framework/native-memory-for-microsoft-agent-framework-with-azure-cosmos-db

### 要約
Microsoft Agent Framework に Azure Cosmos DB を使った durable なメモリ統合が追加されたことを案内する記事です。会話のターンをセッションをまたいで保存できる `CosmosMemoryContextProvider` が紹介されています。

### 開発者にとって重要なこと
エージェントに長期記憶やセッションをまたぐ状態保持を持たせたいチームに関係します。会話の継続性、状態復元、記憶の永続化を Cosmos DB で実装する選択肢になります。

### アクションプラン
- Microsoft Agent Framework で永続メモリが必要かどうかを、既存のエージェント要件と照らして確認する
- Azure Cosmos DB を使える前提があるか、運用・コスト・データ保持の観点で評価する
- 試す場合は、`CosmosMemoryContextProvider` を使った最小構成で会話保持の動作を検証する

### リファレンス
