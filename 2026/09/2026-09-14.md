## Why didn't ReadDirectoryChangesW provide a way to correlate the two sides of a rename operation?

- **Blog:** Oldnewthing
- **Author:** Raymond Chen
- **URL:** https://devblogs.microsoft.com/oldnewthing/20260914-00/?p=112696

### 要約
`ReadDirectoryChangesW` で rename 操作の前後を対応付けできない理由について、設計や実装上の背景を推測する記事です。投稿冒頭では、なぜ相関情報が提供されなかったのかという問いを扱っています。

### 開発者にとって重要なこと
Windows のファイルシステム監視を使う開発者に関係します。rename の通知を正しく扱えないと、同期ツールや監視ツールで誤検知や状態不整合が起きやすくなります。

### アクションプラン
- Windows の変更監視を使うコードで、rename の前後を同一イベントとして扱えない前提を確認する
- 同期・バックアップ・監査系ツールでは、rename の扱いを個別にテストする
- 必要なら、より高レベルな監視 API や独自の相関ロジックの採用を検討する

### リファレンス
- [Why didn't ReadDirectoryChangesW provide a way to correlate the two sides of a rename operation?](https://devblogs.microsoft.com/oldnewthing/20260914-00/?p=112696)

## MulticloudDB SDK: Cross-cloud portability in the coding agent era

- **Blog:** Cosmosdb
- **Author:** Theo van Kraay
- **URL:** https://devblogs.microsoft.com/cosmosdb/multiclouddb-sdk-cross-cloud-portability-in-the-coding-agent-era

### 要約
Java 向けの Multicloud DB SDK を紹介し、Azure Cosmos DB、Amazon DynamoDB、Google Cloud Spanner 間でのクロスクラウド移植性を高める考え方を説明しています。CRUD やクエリを 1 つの API に集約し、プロバイダー選択を切り替えられる点が示されています。

### 開発者にとって重要なこと
マルチクラウドでデータ層を扱う Java チームに関係します。SDK の抽象化により、プロバイダー依存の実装・エラー処理・検証作業を減らせる可能性があります。

### アクションプラン
- Java のデータアクセス層で、クラウド固有実装をどこまで SDK に寄せられるか確認する
- Cosmos DB / DynamoDB / Spanner をまたぐユースケースがある場合、移植コストと検証手順を比較する
- coding agent を使う開発フローでは、AI が扱う API 面を統一できるか評価する

### リファレンス
- [MulticloudDB SDK: Cross-cloud portability in the coding agent era](https://devblogs.microsoft.com/cosmosdb/multiclouddb-sdk-cross-cloud-portability-in-the-coding-agent-era)
