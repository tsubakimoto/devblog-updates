## Go 1.27.2-1 と 1.26.9-1 の Microsoft ビルドが公開

- **Blog:** Go
- **Author:** Davis Goodin
- **URL:** https://devblogs.microsoft.com/go/go-1-27-2-1-and-1-26-9-1-microsoft-builds-now-available

### 要約
Microsoft Build of Go の `v1.27.2-1` と `v1.26.9-1` が公開され、それぞれ上流の Go `1.27.2` と `1.26.9` に対応します。リリースにはセキュリティ修正が含まれ、ダウンロードと変更内容へのリンクが案内されています。

### 開発者にとって重要なこと
Microsoft Build of Go を使う環境では、セキュリティ修正を含む更新版への対応が必要です。どちらのバージョン系列を採用しているかに応じて適切なビルドを選び、既存プロジェクトや CI の互換性を確かめる必要があります。

### アクションプラン
- Microsoft Build of Go を利用する開発者・運用チームは、使用中の系列に応じて `v1.27.2-1` または `v1.26.9-1` への更新を計画する。
- 変更内容とセキュリティ修正を公式リリース情報で確認し、アプリケーションと CI でテストしてから展開する。
- ⚠️ セキュリティ修正を含むため、更新の優先度と本番環境への適用時期をチームで確認する。

### リファレンス
- [Go 1.27.2-1 and 1.26.9-1 Microsoft builds now available](https://devblogs.microsoft.com/go/go-1-27-2-1-and-1-26-9-1-microsoft-builds-now-available)

## Agent Experience (AX) Practitioner Playbook の紹介

- **Blog:** Blog
- **Author:** Waldek Mastykarz
- **URL:** https://devblogs.microsoft.com/blog/introducing-the-agent-experience-ax-practitioner-playbook

### 要約
AI コーディングエージェントが特定の技術を正しく使えるかを評価し、失敗の原因を診断して改善につなげる方法をまとめた AX Practitioner Playbook が公開されました。信頼できる評価基準や実行ゲートの作り方、失敗パターンの分析、変更を仮説として検証して公開するまでの手順を、Cosmos DB や SPFx などの実例とともに扱います。あわせて、Playbook に沿って評価作業を支援する AX Practitioner skill も提供されています。

### 開発者にとって重要なこと
SDK、API、サービス、CLI、MCP サーバー、skill、plugin、ドキュメントなど、エージェントが参照する技術を提供するチームは、モデルの改善を待つだけでなく、エージェントが頼る情報源やツールを改善できます。Playbook は、動作するコードかどうかを含む検証可能な基準で問題を再現し、原因に対応する改善案を評価するための実践的な枠組みになります。

### アクションプラン
- 自社の技術や拡張機能がエージェントにどう使われるか調べる場合は、[AX Practitioner Playbook](https://aka.ms/ax-playbook) を入手し、実際の開発タスクを使った評価シナリオを作る。
- 評価基準には意味的な正しさとコード実行の確認を含め、基準の再現性を確かめてから結果を判断する。
- 失敗時は実行の軌跡を追い、ドキュメント、MCP ツール、skill、plugin、CLI、API など、原因に対応した情報源・機能を修正して仮説を再評価する。
- 必要に応じて AX Practitioner skill を導入し、Playbook の基準に沿ってシナリオや評価基準を点検する。

### リファレンス
- [Introducing the Agent Experience (AX) Practitioner Playbook](https://devblogs.microsoft.com/blog/introducing-the-agent-experience-ax-practitioner-playbook)

## Azure Cosmos DB で Confluent Cloud コネクターをネイティブに利用

- **Blog:** Azure Cosmos DB
- **Author:** Theo van Kraay
- **URL:** https://devblogs.microsoft.com/cosmosdb/introducing-the-native-confluent-cloud-connector-experience-in-azure-cosmos-db

### 要約
Azure Cosmos DB for NoSQL の Azure portal から Confluent Cloud コネクターを検出・作成するネイティブなガイド付き操作が発表されました。Cosmos DB の変更を Kafka に送る方向と、Kafka のレコードを Cosmos DB に書き込む方向の両方を選べ、Azure portal 上でリソース選択や検証、クラスター作成を進められます。Confluent 組織は Azure リソースとして管理され、Microsoft Entra ID のシングルサインオンと Azure 請求に対応します。

### 開発者にとって重要なこと
Cosmos DB の変更を複数の Kafka コンシューマーに配信したり、Kafka イベントから Cosmos DB のアプリケーション向けビューを構築したりする連携の設定を、Cosmos DB アカウントから開始できます。利用には Confluent の組織・環境・クラスターに加え、Kafka トピック、Cosmos DB のデータベースとコンテナー、両サービスへの必要な権限が関係します。

### アクションプラン
- Azure Cosmos DB for NoSQL アカウントの **Integrations > Apache Kafka on Confluent Cloud** を開き、利用する Confluent 組織、環境、クラスターを選択する。
- データの流れに応じて **Send to Confluent** または **Receive from Confluent** を選び、必要な Kafka トピック、Cosmos DB データベース・コンテナー、およびアクセス権限を準備する。
- ガイドの Basics ステップで依存リソースが検証されることを確認し、認証・構成・作成内容をレビューしてからコネクターを作成する。
- 既存の変更フィードや Kafka 連携を置き換えるのではなく、保持・再生や複数コンシューマーなどの要件に照らしてネイティブ連携の適用範囲を評価する。

### リファレンス
- [Introducing the Native Confluent Cloud Connector Experience in Azure Cosmos DB!](https://devblogs.microsoft.com/cosmosdb/introducing-the-native-confluent-cloud-connector-experience-in-azure-cosmos-db)
