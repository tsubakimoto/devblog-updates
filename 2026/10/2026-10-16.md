## What's new in Microsoft Foundry | September 2026

- **Blog:** Foundry
- **Author:** Nick Brady
- **URL:** https://devblogs.microsoft.com/foundry/whats-new-in-microsoft-foundry-september-2026

### 要約
9 月の Microsoft Foundry 更新として、GPT-6 Astra、GPT-6.1 Sol、GPT-6 Luna の GA、Routines と Tool Search の GA、Insights のパブリックプレビューなどが紹介されています。Model Router のセッションアフィニティ、Foundry Local 2.1 のローカルモデル登録、Content Understanding のプレビュー用ツールを含む、エージェント機能・モデル・開発ツールの変更もまとめられています。

### 開発者にとって重要なこと
定期実行やツール定義のオンデマンド読み込みが正式提供となり、エージェントの運用方法を見直せます。一方、Insights や音声エージェント、長時間実行の回復機能などはプレビューで、機能ごとに提供段階や必要な設定が異なります。モデル選定では性能だけでなく、API、リージョン、データゾーン、料金の違いも考慮が必要です。

### アクションプラン
- Foundry の利用チームは、対象ワークフローで Routines と Tool Search を試し、定期実行の承認・配信経路や必要なツール権限を確認する。
- GPT-6 系モデルを検討する場合は、実タスクで品質とコストを比較し、利用リージョン、デプロイ方法、API 互換性、最新料金を確認する。
- Insights、音声エージェント、長時間実行の回復、Content Understanding Toolkit などはプレビューであることを踏まえ、非本番データで検証する。Insights の提案はトレースと同一条件で検証してから適用する。
- Foundry Local 2.1 を利用する場合は、登録する ONNX Runtime GenAI モデルとの互換性と対象ハードウェアを確認する。

## C++ futures part 5: std::future and std::shared_future

- **Blog:** Oldnewthing
- **Author:** Raymond Chen
- **URL:** https://devblogs.microsoft.com/oldnewthing/20261016-00/?p=112778

### 要約
`std::future` はムーブ専用で、値を一度だけ取得する単一消費者向けの型です。`shared_future` に変換するとコピー可能になり、複数の利用者が値を繰り返し参照できますが、取得できるのは `const` 参照のため、変更にはコピーが必要です。記事は、これらの機能を支える共通の内部要素として値を保持・受け渡す `source` の役割を説明しています。

### 開発者にとって重要なこと
非同期処理の結果を一つの処理だけが消費するのか、複数の処理が共有するのかで、適切な future 型と所有権の扱いが変わります。特に `shared_future` では結果を直接変更できず、結果がムーブ専用型の場合は `const` 参照から取り出せない点に注意が必要です。

### アクションプラン
- `std::future` の `get()` を複数回呼ばないようにし、値の受け渡しにはムーブによる所有権移転を使う。
- 複数の利用者が同じ結果を必要とする場合は `shared_future` を検討し、`get()` の戻り値が `const` 参照であることと、コピーコストや型の制約を確認する。
- 非同期処理の設計時に、結果の生成側と消費側が共有する状態のライフサイクルを確認する。
