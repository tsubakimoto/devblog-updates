## Announcing Azure AI Speech LLM 09-2026: Broader locale support

- **Blog:** Foundry
- **Author:** Rena Liu
- **URL:** https://devblogs.microsoft.com/foundry/announcing-azure-ai-speech-llm-09-2026

### 要約
Azure AI Speech の LLM Speech 09-2026 が Fast Transcription API で利用可能になり、アッサム語やベンガル語など11のインド系言語を含む25言語が追加されました。前バージョン比で最大2倍の処理速度と認識品質の向上をうたい、無音音声への対応も改善しています。

### 開発者にとって重要なこと
多言語の音声エージェント、会議記録、コンタクトセンター分析、字幕生成で、対応言語と処理速度の選択肢が広がります。サービス側で自動適用される更新のため、利用者によるモデル移行は不要ですが、実際の音声や業務用語で認識結果を評価することは有用です。

### アクションプラン
- 対象ユースケースの言語・ロケールが追加サポートに含まれるか、公式の言語一覧を確認する。
- 混在言語の音声では locale の指定を省略する設定を検討し、単一言語の音声では既知の locale を指定して精度・遅延を評価する。
- 既存の評価音声で文字起こし品質と処理時間を比較する。サービス側の自動更新に伴う必須作業はない。

## Puzzling out why a program doesn’t work when run from a batch file, but works when double-clicked from Explorer

- **Blog:** The Old New Thing
- **Author:** Raymond Chen
- **URL:** https://devblogs.microsoft.com/oldnewthing/20261026-00/?p=112797

### 要約
エクスプローラーから起動すると動くプログラムがバッチファイルから起動すると失敗する原因として、作業ディレクトリの違いを解説しています。エクスプローラーは起動対象の場所をカレントディレクトリにする一方、バッチファイルでは異なる場所のまま実行される場合があり、`pushd` で移動してから起動し、`popd` で戻す方法が紹介されています。

### 開発者にとって重要なこと
相対パスで付属ファイルを探すアプリケーションは、起動元によって結果が変わる可能性があります。バッチファイルや自動化ジョブの不具合調査では、実行ファイルのパスだけでなくカレントディレクトリや PATH も比較対象になります。

### アクションプラン
- バッチ起動時に失敗する場合、アプリが参照する相対パスと実際のカレントディレクトリを確認する。
- 必要に応じて `pushd` でアプリのディレクトリへ移動して起動し、終了後に `popd` で元のディレクトリへ戻す。
- 作業ディレクトリが原因でない場合は、記事で触れられている `App Paths` による PATH の追加も調査する。

- [Puzzling out why a program doesn’t work when run from a batch file, but works when double-clicked from Explorer](https://devblogs.microsoft.com/oldnewthing/20261026-00/?p=112797)

## PHP2Shell and Azure DevOps: what to check

- **Blog:** DevOps
- **Author:** Josef Sin
- **URL:** https://devblogs.microsoft.com/devops/php2shell-and-azure-devops-what-to-check

### 要約
記事は、2026年10月21日に開示された PHP のリモートコード実行脆弱性 CVE-2026-109618 と CVE-2026-109619 について、Azure DevOps の利用者が確認すべき範囲を説明しています。Azure DevOps Services / Server 自体は PHP で顧客リクエストを処理しませんが、パイプライン、エージェント、コンテナー、デプロイ対象に含まれる PHP は個別に評価・更新が必要です。

### 開発者にとって重要なこと
Azure DevOps 製品の更新だけでは、利用者が管理する PHP ランタイムやイメージは修正されません。Microsoft-hosted agent の更新状況はイメージごとに異なり、self-hosted agent、ジョブコンテナー、アプリケーションに含まれる PHP は各管理者の責任です。PHP CLI や Composer があるだけで、脆弱な HTTP 経路があるとは限らない点にも注意が必要です。

### アクションプラン
- ⚠️ パイプライン、self-hosted agent、ジョブ／アプリケーションコンテナー、デプロイ先で使う PHP とパッケージの完全なリビジョン・提供元を棚卸しし、ベンダー勧告と照合する。
- 修正版の適用状況を確認する。記事記載の upstream 修正版は PHP 8.5.12、8.4.27、8.3.36、8.2.35。ベンダー提供の修正バックポートも対象となる。
- 管理下のホストやイメージを更新し、コンテナーを再ビルド・再デプロイする。PHP を使うアプリケーションでは実行中のバージョンを確認し、必要に応じてワーカーを再起動する。
- Microsoft-hosted agent を使う場合は選択したイメージへの修正展開状況を確認し、更新前に修正が必要ならベンダー修正版の PHP またはパッチ済みコンテナーを使う。

### リファレンス
- [PHP2Shell and Azure DevOps: what to check](https://devblogs.microsoft.com/devops/php2shell-and-azure-devops-what-to-check)

## Keep your investigation between sessions

- **Blog:** Visual Studio
- **Author:** Jason Chlus, Mads Kristensen
- **URL:** https://devblogs.microsoft.com/visualstudio/keep-your-investigation-between-sessions

### 要約
Visual Studio 2026 18.11 では、**New File** からプロジェクトに追加しない Markdown ファイルを作成し、調査メモなどに使えます。Hot Exit のプレビュー設定を有効にすると、未保存の文書や編集状態を Visual Studio の終了後も保持し、次回起動時に復元できます。

### 開発者にとって重要なこと
一時的な調査メモをプロジェクトの成果物にせず、IDE のセッションをまたいで作業を続けられます。Hot Exit は既定で無効で、ファイルをディスクに保存したりソース管理に登録したりすることとは異なります。

### アクションプラン
- 調査メモを試す場合は Ctrl+N から Markdown File を作成する。
- 未保存の状態を復元したい場合は、**Tools > Options > All Settings > Projects and Solutions > General** の **Reopen unsaved documents on solution load or empty environment** を有効にする。
- チームで共有・長期保管するメモは保存先を決めて明示的に保存し、必要ならソース管理に登録する。

### リファレンス
- [Keep your investigation between sessions](https://devblogs.microsoft.com/visualstudio/keep-your-investigation-between-sessions)
