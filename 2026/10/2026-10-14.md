## Azure MCP Server 3.0 stable release: More tools. More possibilities

- **Blog:** Azure SDK Blog
- **Author:** Sandeep Sen
- **URL:** https://devblogs.microsoft.com/azure-sdk/azure-mcp-server-3-0-stable-release

### 要約
Azure MCP Server 3.0 の安定版がリリースされ、Azure Backup、Resilience Management、SRE Agent、Terraform、Advisor、Monitor などを扱うツールが追加されました。ツール契約や構造化レスポンスが改善され、新規リソースには共有キー認証やパブリックネットワークを無効にするなどのセキュリティ既定値が導入されています。2.0 やプレビュー版からは、コマンド名・引数・レスポンス形式・設定ファイルなどに互換性変更があります。

### 開発者にとって重要なこと
Azure 操作を MCP 対応エージェントに連携しているチームは、運用・IaC の作成・コスト最適化に使える機能が増えます。一方、既存のスクリプトや MCP クライアントは引数削除、レスポンス構造、名前空間などの変更に対応する必要があります。データベースクエリツールは破壊的操作になり得るため、権限設定の見直しも重要です。

### アクションプラン
- Azure SDK Blog の 3.x changelog と移行項目を確認し、保存済みプロンプト、スクリプト、クライアントの呼び出し・レスポンス解析をテストする。
- まず開発用サブスクリプションと最小権限の ID で `--read-only` を試し、書き込み操作は既存のレビュー・承認手順のもとで段階的に有効化する。
- ⚠️ データベースクエリの権限、IaC の VM イメージやサイズ、MCP クライアントのプロトコルヘッダー要件をアップグレード前に確認する。

### リファレンス
- [Azure MCP Server 3.0 stable release: More tools. More possibilities](https://devblogs.microsoft.com/azure-sdk/azure-mcp-server-3-0-stable-release)

## Build offline-first apps with Azure DocumentDB and PowerSync

- **Blog:** Azure DocumentDB Blog
- **Author:** Marko Hotti
- **URL:** https://devblogs.microsoft.com/documentdb/build-offline-first-apps-with-azure-documentdb-and-powersync

### 要約
PowerSync が Azure DocumentDB のアルファ版連携を追加し、Azure DocumentDB の Change Streams を使ってクラウド側のデータを端末上の SQLite と同期する構成を紹介しています。端末側ではネットワークが不安定・不通でも読み書きを続け、接続回復後にバックエンド経由で変更を同期できます。同期対象をユーザー、端末、テナントなどに応じて絞り込めます。

### 開発者にとって重要なこと
現場作業、物流、小売など、常時接続に依存できないアプリでオフライン対応を検討するチームに関係します。ただし連携はアルファ版であり、Change Streams、コレクション操作、ドキュメントサイズ、レプリケーション挙動などの制約を実ワークロードで検証する必要があります。

### アクションプラン
- オフライン要件と同期対象データを整理し、端末上の SQLite とクラウド側の Azure DocumentDB のデータフローを設計する。
- PowerSync の Azure DocumentDB ドキュメントで現行の制約を確認し、代表的なデータ量・接続断・競合ケースを使ってアルファ版を評価する。
- ⚠️ アルファ版であることを踏まえ、本番採用はサポート範囲と運用リスクを確認して判断する。

### リファレンス
- [Build offline-first apps with Azure DocumentDB and PowerSync](https://devblogs.microsoft.com/documentdb/build-offline-first-apps-with-azure-documentdb-and-powersync)

## From extraction to action: Using grounding and confidence to build reliable document workflows

- **Blog:** Microsoft Foundry Blog
- **Author:** Joe Filcik
- **URL:** https://devblogs.microsoft.com/foundry/content-understanding-confidence-grounding-hitl

### 要約
Azure Content Understanding の抽出値を根拠（grounding）と信頼度で評価し、人による確認へ振り分ける文書処理ワークフローを紹介しています。保険会社との事例では、1,000 件超の本番文書・22,000 件超のフィールド値で検証し、保留データで確認対象を 41% 減らしながら既知の抽出エラーの 80% 超を対象に含めました。信頼度は一律の閾値で使わず、文書種別・版・入力元・フィールドごとに人手確認済みデータで校正する方法を説明しています。

### 開発者にとって重要なこと
請求書、申請書、保険書類などを自動処理するチームにとって、抽出値の出典を追跡し、誤りの可能性に応じてレビューを優先できる設計が重要です。信頼度スコアは正しさの保証ではなく、事例でも全フィールドを人が確認しており、結果は文書・モデル・設定ごとに校正と継続監視が必要です。

### アクションプラン
- 人手で正解を確認した代表的な本番文書を集め、文書種別・版・入力元およびフィールドごとに抽出精度と信頼度の識別性能を測る。
- 業務上許容できるエラー見逃し率を定め、閾値を校正データで選んだ後、未使用の文書で検証する。空欄値は別ルールで扱う。
- ⚠️ 人手レビューを外す場合は、低信頼度や根拠不十分な値を必ずレビューへ送り、未選択データも含めた本番監視・再校正を行う。

### リファレンス
- [From extraction to action: Using grounding and confidence to build reliable document workflows](https://devblogs.microsoft.com/foundry/content-understanding-confidence-grounding-hitl)
