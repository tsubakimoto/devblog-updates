## Bring Your Own Model is now generally available in Visual Studio

- **Blog:** Visual Studio
- **Author:** Praveen Sethuraman
- **URL:** https://devblogs.microsoft.com/visualstudio/bring-your-own-model-is-now-generally-available-in-visual-studio

### 要約
Visual Studio 18.12 で Bring Your Own Model (BYOM) が一般提供になりました。1 つのプロバイダーに複数の接続設定を保存できるほか、OpenAI 互換のカスタムエンドポイントや LM Studio のローカルモデル、OpenAI Completions / Responses と Anthropic Messages の API 形式、コンテキストサイズやツール呼び出しの設定に対応します。Visual Studio のプロキシ設定との連携や、組織ポリシーによる BYOM の有効・無効化も改善されています。

### 開発者にとって重要なこと
GitHub サインインに依存せず、組織内・ローカル環境を含むモデルを Visual Studio の Agent Mode で利用できるようになります。企業ネットワークや承認済みモデルの運用にも関係するため、エンドポイントの認証・到達性と管理者ポリシーの確認が必要です。

### アクションプラン
- Visual Studio 18.12 を利用する開発者は、Chat のモデルピッカーから **Manage models** を開き、利用するモデルと API 形式に合ったプロバイダー接続を設定する。
- 複数の環境・アカウントを使うチームは、接続に識別しやすい名前を付け、プロキシ経由の接続と Agent Mode の動作を検証する。
- 管理者は組織ポリシーで BYOM を許可するか判断し、利用者に承認済みエンドポイントや認証方法を周知する。

### リファレンス

## Visual Studio Code 1.146

- **Blog:** VS Code Blog
- **Author:** Visual Studio Code Team
- **URL:** https://devblogs.microsoft.com/vscode-blog/visual-studio-code-1.146

### 要約
VS Code 1.146 では、複数プロジェクトのエージェントセッションをまとめる実験的な Inbox mode、チャットの別ウィンドウ表示、エージェントウィンドウでの拡張機能管理、モデル比較の改善などが追加されました。Copilot harness では権限確認の粒度が向上し、サンドボックスで環境変数をマスクする設定や MCP 経由の Skills（プレビュー）にも対応します。一方、Local harness は非推奨となり、2027 年 2 月に削除予定です。

### 開発者にとって重要なこと
Copilot の作業管理や権限・資格情報の保護を改善できる一方、Local harness を使う個人や組織には移行期限があります。Inbox、チャットウィンドウ、拡張機能管理など一部機能は実験的またはプレビューのため、チームの標準ワークフローに採用する前に制約を確認してください。

### アクションプラン
- ⚠️ Local harness を利用中のチームは、2027 年 2 月の削除前に Copilot harness へ移行し、カスタマイズや既存会話の継続方法を移行ガイドで確認する。
- エージェントの権限やシークレットを扱うチームは、改善された権限プロンプトと `chat.agent.sandbox.credentials.envVars` の設定を確認し、信頼する HTTPS ホストを必要最小限にする。
- Inbox mode、チャットウィンドウ、MCP Skills などを試す場合は、プレビュー・実験的機能であることを踏まえて利用環境で検証する。

### リファレンス
- [Visual Studio Code 1.146](https://code.visualstudio.com/updates/v1_146)

## Go 1.27.4-1 and 1.26.11-1 Microsoft builds now available

- **Blog:** Go
- **Author:** Davis Goodin
- **URL:** https://devblogs.microsoft.com/go/go-1-27-4-1-and-1-26-11-1-microsoft-builds-now-available

### 要約
Microsoft が Go 1.27.4-1 と Go 1.26.11-1 のビルドを公開しました。対応する上流リリースには、cgo、`go` コマンド、コンパイラー、リンカー、`net/http` のセキュリティ修正に加え、アセンブラー、ランタイム、暗号関連パッケージなどの不具合修正が含まれます。

### 開発者にとって重要なこと
これらの Go バージョンを利用する開発・ビルド・本番環境では、セキュリティ修正を取り込むための更新が必要です。記事は個別の脆弱性や影響条件までは説明していないため、詳細な適用判断は上流のリリースノートを確認してください。

### アクションプラン
- ⚠️ Go 1.27 または 1.26 を使うチームは、Microsoft build の 1.27.4-1 または 1.26.11-1 へ更新し、CI と実行環境の Go バージョンを揃える。
- 更新後にビルドとテストを実施し、上流の [Go 1.27.4](https://go.dev/doc/devel/release#go1.27.4) および [Go 1.26.11](https://go.dev/doc/devel/release#go1.26.11) のリリースノートで詳細を確認する。

### リファレンス
- [Go 1.27.4-1 and 1.26.11-1 Microsoft builds now available](https://devblogs.microsoft.com/go/go-1-27-4-1-and-1-26-11-1-microsoft-builds-now-available)
