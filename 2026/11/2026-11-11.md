## Resources for the SQL AI Developer

- **Blog:** Azure SQL
- **Author:** Jerry Nixon
- **URL:** https://devblogs.microsoft.com/azure-sql/dp-800-sql-ai-certification

### 要約
SQL と AI の活用例を、データベース運用を支援するエージェント、SQL MCP Server による制御されたデータアクセス、ベクトル／ハイブリッド検索を使う RAG の3つに整理しています。これらの開発スキルを扱う DP-800 試験と Microsoft Certified: SQL AI Developer Associate 認定も紹介しています。

### 開発者にとって重要なこと
SQL データをエージェントに利用させる設計では、公開するデータや操作を限定することと、検索した情報を回答の根拠に使うことが重要です。DP-800 は SQL Server、Azure SQL、Microsoft Fabric の SQL データベースを使う AI 開発に関係します。

### アクションプラン
- SQL MCP Server を検討する場合は、エージェントに公開するデータベースオブジェクト、権限、実行可能な操作を先に定義する。
- RAG を実装するチームは、ベクトル／ハイブリッド検索から埋め込み生成、プロンプト構成、モデル応答処理までの流れを確認する。
- SQL 開発者は DP-800 の対象範囲を確認し、認定が自身やチームのスキル計画に合うか判断する。

### リファレンス
- [Resources for the SQL AI Developer](https://devblogs.microsoft.com/azure-sql/dp-800-sql-ai-certification)

## Preconfigured agents with Microsoft Agent Framework for Go

- **Blog:** Go
- **Author:** Michelle Clayton
- **URL:** https://devblogs.microsoft.com/go/preconfigured-agents-with-microsoft-agent-framework-for-go

### 要約
Microsoft Agent Framework for Go の `agent/harness` パッケージが、エージェントのセッション状態、会話履歴、To-do ツール、ファイルメモリ、Skills、ツール承認、トレースなどを組み合わせる設定を提供します。パッケージは v0.2.0 以降で利用でき、フレームワーク自体はパブリックプレビューです。Plan／Execute モードは振る舞いを指示するもので、ツール利用を禁止したりサンドボックス化したりはしません。

### 開発者にとって重要なこと
共通のエージェント機能をアプリごとに組み立て直す手間を減らし、セッションをまたぐ作業やツール呼び出しの承認・監視を実装しやすくなります。一方、プレビュー段階であり、モードの指示だけでは実行権限や安全性を強制できません。

### アクションプラン
- Go でエージェントを構築するチームは v0.2.0 以降の `agent/harness` を試し、セッション継続、履歴、Skills、トレースを既存要件と照合する。
- ツール実行がデータ変更や外部操作につながる場合は、承認ルールとアプリケーション側の権限制御を明示的に実装する。Plan／Execute 指示をセキュリティ境界として扱わない。
- プレビュー依存を本番採用する前に、API 変更や運用上の制約を検証する。

### リファレンス
- [Preconfigured agents with Microsoft Agent Framework for Go](https://devblogs.microsoft.com/go/preconfigured-agents-with-microsoft-agent-framework-for-go)

## Content Understanding adds GPT-5.6, GPT-6, and GPT-6.1: Choose the right model for your workload

- **Blog:** Foundry
- **Author:** Joe Filcik
- **URL:** https://devblogs.microsoft.com/foundry/content-understanding-adds-gpt-5-6-gpt-6-and-gpt-6-1-choose-the-right-model-for-your-workload

### 要約
Azure Content Understanding で GPT-5.6、GPT-6、GPT-6.1 の各モデル系列が利用可能になり、文書・テキスト・音声・動画処理の選択肢が増えました。文書抽出では品質とコストのバランスに GPT-6.1 Sol、低トークンコストには GPT-6 Luna、高精度が重要な場合の比較候補に GPT-6 Astra を挙げていますが、評価結果はタスクによって異なります。

### 開発者にとって重要なこと
モデルの性能と費用は処理内容によって変わり、文書抽出で最良のモデルが動画や音声でも最良とは限りません。ラベル付きサンプルの追加も精度に影響するため、モデル名や一般評価だけで選定するのではなく、自分のデータで品質とコストを測る必要があります。

### アクションプラン
- Content Understanding の利用者は、対象タスクごとに Sol、Luna、Astra などを代表データで比較し、精度・トークン費用・後工程のレビューコストを評価する。
- 文書抽出ではモデルを上げる前に、ラベル付きサンプルを使った評価も行い、準備コストを含めて比較する。
- 文書、動画、音声など異なる処理では設定を分け、プレビューと一般提供の評価結果を混同しない。

### リファレンス
- [Content Understanding adds GPT-5.6, GPT-6, and GPT-6.1: Choose the right model for your workload](https://devblogs.microsoft.com/foundry/content-understanding-adds-gpt-5-6-gpt-6-and-gpt-6-1-choose-the-right-model-for-your-workload)

## Bring Your Own Model is now generally available in Visual Studio

- **Blog:** Visual Studio
- **Author:** Praveen Sethuraman
- **URL:** https://devblogs.microsoft.com/visualstudio/bring-your-own-model-is-now-generally-available-in-visual-studio

### 要約
Visual Studio 18.12 で Bring Your Own Model (BYOM) が一般提供になり、GitHub サインインなしで外部・社内・ローカルのモデルを利用できます。プロバイダーごとの複数接続、OpenAI 互換カスタムエンドポイントや LM Studio、OpenAI Completions／Responses と Anthropic Messages の API 形式、コンテキストやツール呼び出しなどの設定に対応し、プロキシと組織ポリシーも改善されています。

### 開発者にとって重要なこと
Visual Studio の Agent Mode から組織内やローカルのモデルを使えるようになり、既存のネットワークやモデル運用に合わせた選択肢が広がります。利用にはモデルの到達性と認証が必要で、組織ポリシーにより BYOM が無効化されている場合があります。

### アクションプラン
- Visual Studio 18.12 を使う開発者は、Chat のモデルピッカーから **Manage models** を開き、提供元・API 形式に合う接続を追加して Agent Mode を検証する。
- 複数のアカウントや環境を使う場合は接続に識別しやすい名前を付け、プロキシ経由の接続、認証、ツール呼び出しを試す。
- 管理者は組織ポリシーで BYOM の利用可否を決め、承認済みエンドポイントと認証方法を周知する。

### リファレンス
- [Bring Your Own Model is now generally available in Visual Studio](https://devblogs.microsoft.com/visualstudio/bring-your-own-model-is-now-generally-available-in-visual-studio)

## Visual Studio Code 1.146

- **Blog:** VS Code Blog
- **Author:** Visual Studio Code Team
- **URL:** https://code.visualstudio.com/updates/v1_146

### 要約
VS Code 1.146 では、複数プロジェクトのエージェントセッションを追跡する実験的な Inbox mode、チャットの別ウィンドウ表示（プレビュー）、Agents window での拡張機能管理（実験的機能）、モデル比較の改善などが追加されました。Local harness はこのリリースで非推奨となり、2027 年 2 月に削除予定です。

### 開発者にとって重要なこと
エージェントセッションの整理やチャット作業領域の調整に役立つ一方、新機能の一部はプレビューまたは実験的です。Local harness を使う個人・組織には移行期限があり、Copilot harness への切り替え時にカスタマイズや既存セッションへの影響を確認する必要があります。

### アクションプラン
- ⚠️ Local harness の利用者は、2027 年 2 月の削除前に Copilot harness へ移行し、公式の移行ガイドでカスタマイズ互換性と既存会話の扱いを確認する。
- Inbox mode、チャットウィンドウ、Agents window の拡張機能管理などを使う場合は、プレビュー／実験的機能として開発環境で検証してからチーム標準に採用する。
- Copilot harness の管理ポリシーが必要な組織は、Local harness 移行後のサンドボックスと権限設定を確認する。

### リファレンス
- [Visual Studio Code 1.146](https://code.visualstudio.com/updates/v1_146)

## I didn’t write a program with emoji, but I did use a control character

- **Author:** Raymond Chen
- **URL:** https://devblogs.microsoft.com/oldnewthing/20261111-00/?p=112848

- 記事中の `int 19h` は信頼性の低い再起動手段とされているため、実用コードに転用しない。
