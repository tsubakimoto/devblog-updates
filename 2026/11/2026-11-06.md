## Java OpenJDK October 2026 Patch & Security Update

- **Blog:** Java
- **Author:** Josh Martin-Jaffe
- **URL:** https://devblogs.microsoft.com/java/java-openjdk-october-2026-patch-security-update

### 要約
Microsoft Build of OpenJDK の 2026 年 10 月パッチセットが公開され、JDK 25、21、17、11 向けの更新版が提供されました。上流の修正とセキュリティ勧告が含まれ、ビルドのソースコードも GitHub で確認できます。Microsoft による JDK 11 と 17 のサポートは 2027 年 9 月に終了予定です。

### 開発者にとって重要なこと
Microsoft Build of OpenJDK を運用するチームには、各バージョンの修正・セキュリティ更新の評価と適用が関係します。JDK 11 または 17 を使う環境では、将来のサポート終了を見据えたアップグレード計画も必要です。

### アクションプラン
- 利用中の JDK バージョンに対応するリリースノートと OpenJDK の脆弱性勧告を確認し、更新の影響を評価する。
- 検証環境で該当バージョン（25.0.5.0.2、21.0.13.0.2、17.0.21.0.2、11.0.33）の更新を試し、アプリケーションとビルドの互換性を確認する。
- JDK 11 または 17 を利用している場合、2027 年 9 月のサポート終了に向けて移行計画を立てる。

## Why are we all worked up about atomicity when applying hot-patches if we can just suspend all the threads?

- **Blog:** Old New Thing
- **Author:** Raymond Chen
- **URL:** https://devblogs.microsoft.com/oldnewthing/20261106-00/?p=112838

### 要約
プロセス内のスレッドを一時停止しても、別プロセスから新しいスレッドを作成・再開される可能性があるため、コードのホットパッチを安全に適用できるとは限りません。可変長命令を使う x86 では、命令の途中から実行を再開する危険もあり、パッチ適用時の原子性が重要です。さらに、別の `WriteProcessMemory` による同時書き込みは原子的でないため、競合する更新も問題になります。

### 開発者にとって重要なこと
Windows のホットパッチやプロセス内コード変更を設計・解析する開発者にとって、単なるスレッド停止では競合を排除できないことを示す解説です。特にスレッド注入や外部プロセスからのメモリ書き込みを含む仕組みでは、命令境界と更新の原子性を考慮する必要があります。

### アクションプラン
- 独自のコード更新機構を実装・保守している場合、スレッド停止だけに依存せず、命令境界・新規スレッド・同時メモリ書き込みを含む競合条件を見直す。
- Windows の予約されたホットパッチ領域を変更する独自ツールがある場合、サポートされる方法かどうかを確認する。
- 詳細な背景と制約は記事本文を参照する。

## Work IQ: SharePoint Tools

- **Blog:** Microsoft 365 Developer
- **Author:** Paolo Pialorsi、Patrick Rodgers
- **URL:** https://devblogs.microsoft.com/microsoft365dev/work-iq-sharepoint-mcp-tools

### 要約
Work IQ API に SharePoint MCP ツールが追加され、プレビューとしてカスタムアプリやエージェントから SharePoint のコンテンツや操作を利用できるようになります。60 超の操作を個別ツールとして登録する代わりに、`search_paths`、`get_schema`、`do_action` で必要な操作を実行時に発見・呼び出します。操作はサインイン中のユーザーの権限で行われ、`WorkIQ.Read` は読み取り系、`WorkIQ.Act` は全ツールへのアクセスを提供します。

### 開発者にとって重要なこと
SharePoint のファイル、リスト、検索、承認などを扱うエージェントを開発するチームが対象です。実行時にスキーマを確認して引数を組み立てる設計と、ユーザーに委任された権限および読み取り・変更権限の区分を考慮する必要があります。

### アクションプラン
- SharePoint を操作するエージェントを開発している場合、プレビューの SharePoint MCP と Work IQ の要件を確認し、必要な `WorkIQ.Read` または `WorkIQ.Act` スコープを選ぶ。
- `get_site_key` で得た `siteKey` を使い、`search_paths` → `get_schema` → `do_action` の流れを検証する。引数の形式や SharePoint 内部フィールド名は返されたスキーマに従う。
- ユーザーに許可された範囲を超えてアクセスできないことを踏まえ、読み取り・変更操作と委任権限をテストする。
- プレビュー機能の提供状況や制約は、Microsoft Learn の案内を参照する。
