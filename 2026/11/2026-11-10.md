## Automatic MSBuild configuration for the Microsoft C++ Language Server in Copilot CLI

- **Blog:** Cppblog
- **Author:** Sinem Akinci
- **URL:** https://devblogs.microsoft.com/cppblog/automatic-msbuild-configuration-for-the-microsoft-c-language-server-in-copilot-cli

### 要約
Microsoft C++ Language Server が Copilot CLI の起動時に MSBuild ベースの C++ プロジェクトを検出し、必要に応じて `compile_commands.json` を自動生成するようになりました。Visual Studio の MSBuild ツールを使って `.vcxproj` や property sheets からコンパイラ オプション、include パス、プリプロセッサ定義を読み取り、追加の設定スキルなしでコード解析に利用します。

### 開発者にとって重要なこと
MSBuild プロジェクトで定義・参照検索や診断の精度を高めるための事前設定が減り、Copilot CLI でリポジトリを開いてから意味解析を使い始めるまでが簡単になります。自動化されるのはコンパイルデータベースの生成のみで、インストールや前提条件、EULA の承諾は引き続き必要です。CMake など他のビルドシステムでは従来どおり別途設定します。

### アクションプラン
- Copilot CLI で MSBuild ベースの C++ リポジトリを開き、定義・参照検索や診断がプロジェクト設定を反映するか確認する。
- 初回設定の進捗は `/lsp logs` で確認し、必要に応じて C++ Language Server の構成ドキュメントでタイムアウトや自動設定の無効化を確認する。
- CMake や独自ビルドを使うチームは、既存の `compile_commands.json` または記事で案内されるビルド抽出手順を利用する。

### リファレンス
- [Automatic MSBuild configuration for the Microsoft C++ Language Server in Copilot CLI](https://devblogs.microsoft.com/cppblog/automatic-msbuild-configuration-for-the-microsoft-c-language-server-in-copilot-cli)

## Activation via AppUserModelId

- **Blog:** Insidemsix
- **Author:** Howard Kapustein
- **URL:** https://devblogs.microsoft.com/insidemsix/activation-via-appusermodelid

### 要約
パッケージ化された Windows アプリは、`IApplicationActivationManager::ActivateApplication()` に AppUserModelId (AUMID) を渡して直接起動できます。記事では AUMID がパッケージ ファミリー名と Package Relative Application Id (PRAID) を `!` で連結した値であることを説明し、引数付き起動を含む C、C++、C# の例を紹介しています。

### 開発者にとって重要なこと
ランチャー、テストツール、他アプリとの連携から MSIX アプリを起動する際に、実行ファイルのパスに依存せずアプリを特定できます。正しい package family name と manifest の Application Id が必要で、COM の初期化や起動エラー処理も実装対象です。

### アクションプラン
- MSIX アプリを外部ツールから起動するチームは、パッケージ ファミリー名と manifest の Application Id から AUMID を構成し、対象環境で起動を検証する。
- 起動引数がある場合は、使用する言語の例を参考に引数の受け渡しと COM エラー処理を確認する。

### リファレンス
- [Activation via AppUserModelId](https://devblogs.microsoft.com/insidemsix/activation-via-appusermodelid)

## Announcing .NET 11

- **Blog:** .NET
- **Author:** .NET Team
- **URL:** https://devblogs.microsoft.com/dotnet/announcing-dotnet-11

### 要約
.NET 11 のリリースが発表され、C# 15、ASP.NET Core、.NET MAUI、SDK、ランタイム、ライブラリ、Entity Framework Core 11 などの更新が紹介されました。主な内容には C# の union types と closed hierarchies、SDK 起動や MSBuild の改善、Web・AI 開発機能、ライブラリの追加 API が含まれます。.NET 11 は 2 年サポートの STS リリースで、.NET 10 は引き続き LTS として利用できます。

### 開発者にとって重要なこと
新機能だけでなく、SDK の既定動作、アプリの実行性能、対応する言語・フレームワークの更新が開発・運用双方に影響します。EF Core 11 は .NET 11 が必要で、Runtime Async や一部の AI・MAUI 機能はプレビューまたは実験的です。アップグレード判断では依存関係や breaking changes、サポート期間を確認する必要があります。

### アクションプラン
- .NET チームは .NET 11 の [what's new](https://learn.microsoft.com/dotnet/core/whats-new/dotnet-11/overview) と各コンポーネントの breaking changes を確認し、アプリと CI で互換性・性能を検証する。
- 新規導入またはアップグレードでは STS の 2 年サポートと .NET 10 LTS を比較し、チームの更新サイクルに合うターゲットを選ぶ。
- C# 15、ASP.NET Core、MAUI、AI、EF Core の機能は、採用する機能の安定性・要件・プロバイダー互換性を個別に確認する。プレビュー機能は本番導入前に制約を評価する。

### リファレンス
- [Announcing .NET 11](https://devblogs.microsoft.com/dotnet/announcing-dotnet-11)

## Go 1.25.14-2 Microsoft build now available

- **Blog:** Go
- **Author:** Davis Goodin
- **URL:** https://devblogs.microsoft.com/go/go-1-25-14-2-microsoft-build-now-available

### 要約
Microsoft が、Go 1.25 系を引き続き利用しているユーザー向けに、証明書失効に関する CVE-2026-111943 の修正をバックポートした Go 1.25.14-2 を一度限りのリリースとして公開しました。このビルドには他の CVE 修正は含まれず、Go 1.25 はサポート終了済みで未修正の既知の脆弱性も残るため、記事はサポート対象の Go 1.26 または 1.27 の最新パッチ版へのアップグレードを推奨しています。

### 開発者にとって重要なこと
Go 1.25.14-2 は恒久的なサポート再開や包括的なセキュリティ更新ではありません。Go 1.25 を使い続けるサービスやビルド環境は、対象の証明書失効問題への対処に加えて、未修正の脆弱性リスクを抱えます。

### アクションプラン
- ⚠️ Go 1.25 を使うチームは、サポート対象の Go 1.26 または 1.27 の最新パッチ版へ移行し、ビルド・テストとデプロイ環境のランタイムを更新する。
- 直ちに移行できない場合に限り、Go 1.25.14-2 で CVE-2026-111943 を緩和しつつ、未修正の脆弱性が残ることをリスクとして扱い、移行計画を進める。

### リファレンス
- [Go 1.25.14-2 Microsoft build now available](https://devblogs.microsoft.com/go/go-1-25-14-2-microsoft-build-now-available)
