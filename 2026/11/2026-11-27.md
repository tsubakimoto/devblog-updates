## Could we use the CoreApplication Properties to manage the lifetime of an object that refuses to be marshaled?

- **Blog:** Oldnewthing
- **Author:** Raymond Chen
- **URL:** https://devblogs.microsoft.com/oldnewthing/20261127-00/?p=112901

### 要約
`INoMarshal` を実装するオブジェクトは `RoGetAgileReference` で agile reference を作成できず、`CoreApplication.Properties` に格納しようとしても `CO_E_NOT_SUPPORTED` で失敗します。利用するには、元のオブジェクトを marshalable なラッパーで包み、そのラッパーを使ってアクセスします。ラッパーを `CoreApplication.Properties` に登録してキーで引き直す方法も考えられますが、ラッパー自体を保持する方が簡潔で、Properties は追加の価値をもたらしません。

### 開発者にとって重要なこと
marshal できない COM / WinRT オブジェクトをアパートメント境界を越えて扱う Windows 開発者に関係します。`CoreApplication.Properties` は非 marshalable オブジェクトを保管する回避策や、ラッパーのライフタイム管理先にはならず、アパートメント制約を守るラッパー設計が必要です。

### アクションプラン
- `INoMarshal` オブジェクトを `CoreApplication.Properties` に直接格納しようとしていないか確認する。
- オブジェクトを marshalable なラッパーで包み、呼び出し元アパートメントの制約を守って元のオブジェクトへアクセスする。
- ラッパーを利用する期間中はその参照を直接保持し、不要なキー登録・検索・削除の仕組みを追加しない。
