## Microsoft Agent Framework repository update

- **Blog:** Agent Framework
- **Author:** Dan Taylor
- **URL:** https://devblogs.microsoft.com/agent-framework/microsoft-agent-framework-repository-update

### 要約
Microsoft Agent Framework の Python パッケージ `agent-framework` 1.26.1 と 1.26.2 が、2026 年 11 月 17 日に不正に PyPI へ公開され、認証情報を窃取するコードを含んでいたことが報告されました。該当バージョンは PyPI から削除済みですが、リポジトリは安全性を確認できるまで利用停止となり、再開時期は未定です。影響するのはこの Python メタパッケージで、1.26.0 以前、.NET パッケージ、Semantic Kernel は影響を受けません。

### 開発者にとって重要なこと
該当バージョンはアプリケーションがパッケージを import しなくても、Python 起動時にコードが実行される可能性があります。過去に導入した環境では、クラウド、CI/CD、レジストリなどの認証情報が漏えいしたものとして扱う必要があります。

### アクションプラン
- `agent-framework` 1.26.1 / 1.26.2 の導入有無を、ロックファイル、`pip freeze`、CI ログ、コンテナー、内部ミラー、キャッシュで確認する。
- 該当バージョンを導入していた場合は環境を侵害済みとして扱い、アクセス可能だった認証情報をローテーションし、環境をクリーンなイメージから再構築する。該当環境を単にダウングレードしない。
- 該当版を導入していない場合も、当面は `agent-framework==1.26.0` または必要なサブパッケージのバージョンを固定する。

## Visual Studio Code 1.148

- **Blog:** VS Code Blog
- **Author:** Visual Studio Code Team
- **URL:** https://devblogs.microsoft.com/vscode-blog/visual-studio-code-1.148

### 要約
VS Code 1.148 では、Agent Host のチャット応答開始が従来の Stable 版より平均 30% 高速化しました。エージェント作業中のスリープ抑止、リモート環境の worktree クリーンアップ、リモート向けサンドボックスプロファイル、設定ファイルなしでエージェント用 Dev Container を作成する機能も追加・改善されています。これらの一部は Preview または Experimental です。

### 開発者にとって重要なこと
エージェントを使った作業の継続性やリモート開発の管理が改善されます。Dev Container やサンドボックスを使えば、エージェント作業を分離した環境で実行できますが、試験的な機能はチームの標準環境へ導入する前に挙動を確認する必要があります。

### アクションプラン
- VS Code 1.148 へ更新し、エージェント作業でチャット応答やリモート環境管理の改善を確認する。
- 長時間のエージェント作業がある場合は `sessions.keepAwakeWhileWorking` の設定を確認し、電源接続時のみ・常時・無効から運用に合うモードを選ぶ。
- Dev Container、リモートサンドボックス、worktree クリーンアップを試す場合は Preview / Experimental の制約と既存ワークフローへの影響を検証してからチームへ展開する。

## Why did it seem that the entries in the CoreApplication Properties expired when the source application shut down?

- **Blog:** Oldnewthing
- **Author:** Raymond Chen
- **URL:** https://devblogs.microsoft.com/oldnewthing/20261125-00/?p=112895

### 要約
`CoreApplication.Properties` に保存したエントリ自体は、追加元のアパートメントが終了しても削除されません。一方、保存したオブジェクトが non-agile なら、そのオブジェクトは作成元のスレッドに依存し、アパートメント終了後に利用できなくなることがあります。つまり、消えたように見えるのはエントリではなく値のオブジェクトです。

### 開発者にとって重要なこと
COM オブジェクトのアジリティとアパートメントのライフタイムを区別しないと、`CoreApplication.Properties` の値が消失したように誤認する可能性があります。C# や標準的な C++/WinRT などでは通常 agile ですが、明示的に non-agile にした実装などでは注意が必要です。

### アクションプラン
- `CoreApplication.Properties` に格納するオブジェクトの実装方式とアジリティを確認する。
- 元アパートメントの終了後に値を使うコードでは、オブジェクトの有効期間と COM プロキシ経由の呼び出しを確認する。

## Do inconsistent docs hurt AI coding agents?

- **Blog:** Microsoft for Developers
- **Author:** Waldek Mastykarz
- **URL:** https://devblogs.microsoft.com/blog/do-inconsistent-docs-hurt-ai-coding-agents

### 要約
Dev Proxy のドキュメントに実在した 3 種類の矛盾を使い、3 つのモデルで約 140 回のエージェント実行を比較した調査です。エージェントは矛盾に気づいても古い記述に従うことがあり、実行時に検出できる間違いでも修正までにトークンや手順を余分に使いました。また、CI まで発覚しない誤りでは、壊れた成果物を完成したと報告するケースもありました。別の文書やインストール済みツールなど第二の情報源を確認したエージェントは、誤りを避けていました。

### 開発者にとって重要なこと
古いサンプルや矛盾した仕様は、人だけでなく AI コーディングエージェントの生成結果にも影響します。特にローカルで実行できず CI で初めて失敗する設定は、エージェントが問題に気づけず、未検証の成果物が残るリスクがあります。

### アクションプラン
- ドキュメントを管理するチームは、API リファレンスだけでなく関連する手順書、サンプル、CI 設定も変更時に照合する。
- エージェントにコードを作らせる際は、リンク先の手順だけに依存せず、関連リファレンスやツールの実際の設定・バージョン情報と照合させる。
- 生成コードを実行できない場合は、CI などで検証しないと見つからないバージョン指定や設定値を重点的にレビューする。

### リファレンス
- [Do inconsistent docs hurt AI coding agents?](https://devblogs.microsoft.com/blog/do-inconsistent-docs-hurt-ai-coding-agents)

## Action required: Update app-only permissions for SharePoint tenant App Catalog writes

- **Blog:** Microsoft365dev
- **Author:** SharePoint team
- **URL:** https://devblogs.microsoft.com/microsoft365dev/action-required-update-app-only-permissions-for-sharepoint-tenant-app-catalog-writes

### 要約
2027 年 1 月 31 日以降、SharePoint テナント App Catalog への特定の直接 app-only 書き込みには、Office 365 SharePoint Online リソース上の `SharePointTenantSettings.ReadWrite.All` アプリケーション権限が必要になります。`Sites.ReadWrite.All` や `Sites.FullControl.All` だけではこの追加要件を満たしません。管理者 UI からの操作や委任認証、読み取り・削除操作などは対象外です。

### 開発者にとって重要なこと
テナント App Catalog へパッケージを追加・更新する CI/CD、無人 PnP PowerShell、SharePoint REST / CSOM の app-only 自動化が影響を受ける可能性があります。同名の Microsoft Graph 権限では代替できず、SharePoint への直接呼び出しで使うトークンに SharePoint Online リソース向けの権限が必要です。

### アクションプラン
- テナント App Catalog への書き込みを行う自動化を洗い出し、認証方式と操作内容から対象ワークフローを特定する。
- 対象アプリに Office 365 SharePoint Online リソースの `SharePointTenantSettings.ReadWrite.All` アプリケーション権限を付与し、テナント管理者の同意を得る。
- 認証情報を更新して新しい SharePoint アクセストークンを取得し、パッケージの追加・更新や Tenant-Wide Extensions の操作を期限前に再テストする。既存の他の権限も必要に応じて維持する。
- ⚠️ 2027 年 1 月 31 日までに対応する。Microsoft Graph リソース上の同名権限を、SharePoint Online リソース向け権限の代わりに付与しない。

### リファレンス
- [Action required: Update app-only permissions for SharePoint tenant App Catalog writes](https://devblogs.microsoft.com/microsoft365dev/action-required-update-app-only-permissions-for-sharepoint-tenant-app-catalog-writes)
