## Intelligent Terminal 0.3: A new way to manage your tabs and agents

- **Blog:** Commandline
- **Author:** Hamza Usmani
- **URL:** https://devblogs.microsoft.com/commandline/intelligent-terminal-v0-3-a-new-way-to-see-and-manage-your-tabs-and-agents

### 要約
Intelligent Terminal 0.3 では、ターミナルとエージェントのタブを一覧できるサイドバーが既定になり、エージェントの状態表示、タブのピン留め、ペインの確認、エージェントだけに絞るフィルターが追加されました。開いているタブや過去のエージェントセッションを横断する検索、他のウィンドウで実行中のセッションの再表示、ウィンドウを閉じても選択したタブを動かし続けるヘッドレスモードにも対応します。

### 開発者にとって重要なこと
複数のエージェント CLI やシェルを並行利用する開発者は、作業状態やリポジトリ情報をターミナルを切り替えずに把握しやすくなります。既存の横型タブ表示も選択できるため、従来の操作を維持しながら移行できます。

### アクションプラン
- Microsoft Store または GitHub のリリースから 0.3 に更新し、サイドバーでエージェントの状態・作業ディレクトリ・Git 情報を表示する設定を試す。
- 過去のセッション検索やヘッドレスモードを使う場合は、再開する作業とウィンドウ終了後も実行を続けるタブをチームの運用に合わせて選ぶ。
- 横型タブを使い続けたい場合は、タブのコンテキストメニューまたは Settings > Appearance > Tab Layout でレイアウトを切り替える。

### リファレンス
- [Intelligent Terminal 0.3: A new way to manage your tabs and agents](https://devblogs.microsoft.com/commandline/intelligent-terminal-v0-3-a-new-way-to-see-and-manage-your-tabs-and-agents)

- **Author:** Karthik Vijayan
- **URL:** https://devblogs.microsoft.com/foundry-on-windows/coding-ai-on-windows-pcs-quality-efficiency

### アクションプラン
- ローカル推論を検討する場合は、記事で扱うハードウェアとモデルの要件、品質・速度の評価条件を確認する。
- クラウド利用との比較では、モデルの応答品質、処理時間、実行環境のコスト、データ取り扱いを自分のコーディング作業で測定する。
- ハードウェア導入を判断する前に、記事本文のベンチマークと制約を確認し、自組織のワークロードに当てはめて評価する。

## Deprecation notice: Low-trust SharePoint add-ins in SharePoint Server Subscription Edition

- **Blog:** Microsoft365dev
- **Author:** SharePoint team
- **URL:** https://devblogs.microsoft.com/microsoft365dev/deprecation-notice-low-trust-sharepoint-add-ins-in-sharepoint-server-subscription-edition

### 要約
SharePoint Server Subscription Edition の low-trust SharePoint Add-ins は、2027年1月12日にサポート終了となり、2027年1月の公開更新で既定で無効化されます。組織には該当ソリューションを特定し、SharePoint Framework (SPFx) などのサポート対象への移行計画を立てるよう案内しています。SharePoint REST、CSOM、JSOM API は影響を受けません。

### 開発者にとって重要なこと
SharePoint Server Subscription Edition 上で low-trust Add-ins を稼働させている組織は、期限までに影響範囲の把握と移行を行う必要があります。関連する REST、CSOM、JSOM API 自体の廃止ではないため、API を利用しているだけのソリューションとは切り分けが必要です。

### アクションプラン
- SharePoint Server Subscription Edition のサイトとソリューションを棚卸しし、low-trust Add-ins の利用有無と所有チームを特定する。
- ⚠️ 該当する Add-ins は、2027年1月12日のサポート終了と1月の既定無効化に間に合うよう、SPFx などへの移行または代替策を計画・検証する。
- REST、CSOM、JSOM の利用のみであれば今回の変更対象ではないことを確認し、Add-ins 自体の依存と混同しない。

### リファレンス
- [Deprecation notice: Low-trust SharePoint add-ins in SharePoint Server Subscription Edition](https://devblogs.microsoft.com/microsoft365dev/deprecation-notice-low-trust-sharepoint-add-ins-in-sharepoint-server-subscription-edition)

## Give your coding agent a head start with Microsoft Agent Framework skills for .NET and Python

- **Blog:** Agent Framework
- **Author:** Eduard van Valkenburg
- **URL:** https://devblogs.microsoft.com/agent-framework/give-your-coding-agent-a-head-start-with-microsoft-agent-framework-skills-for-net-and-python

### 要約
Microsoft Agent Framework の .NET 用と Python 用のビルダースキルが公開され、対応する Agent Skills 形式のコーディングエージェントに導入できるようになりました。スキルは適切なパターンの選択からツール、セッション、ワークフロー、ホスティングの実装までを支援する開発時のガイダンスであり、出荷するアプリのランタイム機能ではありません。

### 開発者にとって重要なこと
Agent Framework アプリを開発するチームは、Microsoft が保守する言語別のガイダンスをコーディングエージェントから利用できます。アプリ本体の SDK やモデル認証は別途必要で、エージェントが Agent Skills 形式に対応していることも前提です。

### アクションプラン
- 対応クライアントを確認し、.NET では `gh skill install microsoft/agent-framework agent-framework-builder-dotnet@main`、Python では `gh skill install microsoft/agent-framework agent-framework-builder-python@main` などで対象のスキルを導入する。
- 再現可能なガイダンスが必要なチームは、`main` の代わりにタグまたはコミットを指定してバージョンを固定する。
- スキルを試す際は、プロジェクトの SDK・モデル認証要件を整え、複雑さに見合う最小のエージェント／ワークフローを選ぶ。追加の仕様調査には Microsoft Learn MCP の利用も検討する。

### リファレンス

## There are things with ranks, but it’s not always clear what the ranks mean

- **Blog:** The Old New Thing
- **Author:** Raymond Chen
- **URL:** https://devblogs.microsoft.com/oldnewthing/20261104-00/?p=112830/

### 要約
Windows の複数の機能に登場する「rank」について、値の大小が何を意味するかは機能ごとに異なり、ドキュメントだけでは順序が読み取りにくい場合があると解説しています。SQL Server の全文検索では高い rank が関連性の高さを表す一方、Windows Package Graph のパッケージ依存関係では、同じ rank の場合の挿入順は説明されていても異なる rank 間の優先順が明確でない例を挙げています。

### 開発者にとって重要なこと
API や検索機能に「rank」という語があっても、値の大小や優先順を共通の規則として推測できません。ランキング値を使って結果や依存関係を決めるコードでは、対象機能の仕様を個別に確認する必要があります。

### アクションプラン
- SQL Server の全文検索や Windows のパッケージ依存関係で rank を利用する場合は、対象 API の仕様と実際の順序をそれぞれ確認する。
- ドキュメントに大小の意味が記載されていない場合は、値の比較方向を仮定せず、検証コードや問い合わせで動作を確かめる。

### リファレンス
- [There are things with ranks, but it’s not always clear what the ranks mean](https://devblogs.microsoft.com/oldnewthing/20261104-00/?p=112830/)
