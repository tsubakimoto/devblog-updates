## Announcing GA: DocumentDB extension for Visual Studio Code

- **Blog:** Documentdb
- **Author:** Sandeep S. Nair
- **URL:** https://devblogs.microsoft.com/documentdb/vscode-extension-ga

### 要約
Azure DocumentDB 向け Visual Studio Code 拡張機能が一般提供になりました。ダッシュボードやデータ探索、クエリ分析、インデックス調整を行うビジュアルモードと、統合シェルを使うコマンドモードを同じ接続で利用できます。Microsoft Entra ID と Azure VM のマネージド ID による認証に対応し、DocumentDB Local、OSS DocumentDB、その他の MongoDB 互換環境もサポートします。

### 開発者にとって重要なこと
Azure DocumentDB や MongoDB 互換データベースを扱う開発者は、VS Code 内でデータの確認からシェル操作、クエリ分析、インデックス管理まで行えるようになります。Azure 環境では Entra 認証の接続をビジュアル操作とシェルで共有でき、別ツール間の認証切り替えを減らせます。

### アクションプラン
- Azure DocumentDB または MongoDB 互換環境を利用する開発者は、VS Code Marketplace から拡張機能をインストールし、既存の接続・クエリ・インデックス調整の手順を評価する。
- Azure 接続では Entra ID または Azure VM のマネージド ID を使う構成を確認し、チームのアクセス方針と合うか検証する。
- ローカル開発や他の MongoDB 互換環境が必要な場合は、DocumentDB Local と各環境への接続サポートをドキュメントで確認する。

## MSVC Build Tools version 14.52 now generally available

- **Blog:** Cppblog
- **Author:** Russell Hadley
- **URL:** https://devblogs.microsoft.com/cppblog/msvc-build-tools-version-14-52-now-generally-available

### 要約
MSVC Build Tools 14.52 が一般提供となり、長期サポート (LTS) リリースとして Visual Studio 2026 18.12 Stable と 18.11 LTSC で利用できます。`/std:c++23` による C++23 の本番利用と、C++23 機能を完備した標準ライブラリに加え、x64／ARM64 のコード生成改善、C++ Dynamic Debugging の一般提供などが含まれます。`constexpr` の `<cmath>`／`<cstdlib>` 対応は `/Zc:cmath` によるオプトインです。

### 開発者にとって重要なこと
C++ チームは、環境の更新頻度に応じて Stable または LTSC を選びながら、14.52 をサポート対象の共通ツールセットとして採用できます。C++23 への移行、C++ モジュールの信頼性、ARM64／x64 の最適化や APX 対応を検討するプロジェクトに関係します。

### アクションプラン
- C++ チームは Visual Studio Installer で Visual Studio 2026 と必要なアーキテクチャの MSVC 14.52 コンポーネントを導入し、CMake または MSBuild のツールセット選択を確認する。
- 更新前に CI と開発環境を含むビルドを実行し、C++23、モジュール、対象アーキテクチャのコード生成をプロジェクト要件に沿って検証する。
- `<cmath>`／`<cstdlib>` の `constexpr` 対応を使う場合は `/Zc:cmath` が必要な点を確認し、Stable と LTSC のサービシング方針もチームで選定する。

### リファレンス
- [MSVC Build Tools version 14.52 now generally available](https://devblogs.microsoft.com/cppblog/msvc-build-tools-version-14-52-now-generally-available)

## Microsoft 365 Developer Program updates: new sandbox options and retirement of legacy sandboxes

- **Blog:** Microsoft365dev
- **Author:** Microsoft 365 Platform team
- **URL:** https://devblogs.microsoft.com/microsoft365dev/microsoft-365-developer-program-updates-new-sandbox-options-and-retirement-of-legacy-sandboxes

### 要約
Microsoft 365 Developer Program は、オプションの有料アドオンを利用できる新しいサンドボックスモデルへ移行し、従来のレガシーサンドボックスを終了します。対象者は引き続き無料の E5 開発者サンドボックスを利用できますが、ダッシュボードで「Legacy sandbox」と表示される場合は新しいテナントへの移行が必要です。新しいサンドボックスには別のドメインとテナント ID が割り当てられ、データや構成は自動移行されません。

### 開発者にとって重要なこと
レガシーサンドボックスを利用している開発者は、現在の契約期間終了後に環境とデータが削除される可能性があります。引き続き対象資格がある場合は最後の 60 日更新期間に移行できますが、資格がない場合は更新されません。新しい環境への移行には、アプリの再デプロイと設定の再作成が必要です。

### アクションプラン
- Microsoft 365 Developer Program の利用者は、登録アカウントでダッシュボードを確認し、「Legacy sandbox」の表示、期限、通知メールの削除日を確認する。
- ⚠️ レガシーサンドボックスが対象なら、期限前に必要なデータをバックアップし、新しいサンドボックスでアプリを再デプロイして設定を再作成する。旧テナントの内容は自動移行されず、期限後は最終的に復元できません。
- 新しい E5 開発者サンドボックスは適格な開発者には無料ですが、請求アカウントでの確認が必要です。有料アドオンや通常利用するサブスクリプションを購入する場合は、費用とライセンス要件を別途確認する。
- 移行条件と適格性は記事中の Microsoft Learn とレガシーサブスクリプション終了 FAQ で確認する。
