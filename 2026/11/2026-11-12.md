## Bring Your Expertise to Git-Ape

- **Blog:** All Things Azure
- **Author:** davidwright、Arnaud Lheureux
- **URL:** https://devblogs.microsoft.com/all-things-azure/bring-your-expertise-to-git-ape-the-platform-engineering-framework

### 要約
Git-Ape の Community Skills により、専門知識を手順・スクリプト・参考資料を含むスキルとして共有し、利用者が検索して個別に導入できる仕組みを紹介しています。複数スキルをまとめる pack のプレビュー・承認フローも説明されていますが、pack support と AWS skills pack は提案中の機能として案内されています。

### 開発者にとって重要なこと
プラットフォームチームや専門家は、反復可能な作業手順をエージェント向けに配布しやすくなります。一方、スキルの検索・導入は実行と別であり、配布元・ソース・保存先を確認してから承認する運用が重要です。

### アクションプラン
- Git-Ape を利用している場合、導入元のレジストリとバージョンで目的のスキルが見つかるか確認する。
- チームでスキルを導入する前に、指示・スクリプト・参照資料と保存先をレビューし、実行範囲を決める。
- pack support が必要な場合は、記事からリンクされた提案の進捗を確認する。

### リファレンス
- [Bring Your Expertise to Git-Ape](https://devblogs.microsoft.com/all-things-azure/bring-your-expertise-to-git-ape-the-platform-engineering-framework)

## Challenges of building machine learning compilers across varying hardware architecture

- **Blog:** Foundry On Windows
- **Author:** Rutvi Trivedi ほか（追加協力: Justin Stoecker、Sheil Kumar）
- **URL:** https://devblogs.microsoft.com/foundry-on-windows/machine-learning-compilers-challenges-hardware

### 要約
多様な GPU・NPU で性能と移植性を両立する機械学習コンパイラーの課題を解説しています。複数段階の IR、デバイス固有および非依存の最適化、演算融合、スケジューリングやメモリ管理を組み合わせる必要性を述べ、Windows ML と DirectX Compute Graph Compiler などの方向性を予告しています。

### 開発者にとって重要なこと
ローカル AI や複数のハードウェアを対象とする開発では、単一演算の性能だけでなく、モデル全体の最適化やデバイス間の一貫性が課題になります。記事は技術的な展望であり、具体的な利用可能機能や導入手順の発表ではありません。

### アクションプラン
- Windows 上でローカル AI を開発している場合、使用中のハードウェアごとの性能・互換性要件を整理する。
- コンパイラー選定では、演算対応だけでなく、融合・データ移動・フォールバックを含むモデル全体の挙動を評価する。
- 詳細な製品方針が必要な場合は、記事で案内されている Microsoft Ignite 2026 の BRK388 と今後の Windows ML / DirectX 発表を確認する。

### リファレンス

## C++ Dynamic Debugging is now generally available

- **Blog:** Cppblog
- **Author:** David Li
- **URL:** https://devblogs.microsoft.com/cppblog/c-dynamic-debugging-is-now-generally-available

### 要約
C++ Dynamic Debugging が Visual Studio 2026 の全チャネルと Microsoft C++ (MSVC) Build Tools 14.52 で一般提供になりました。最適化ビルドの実行性能を保ちながら、ブレークポイントやステップ実行時に対象関数の最適化を動的に解除し、ローカル変数やインライン関数を調べられます。

### 開発者にとって重要なこと
ゲームや大規模な C++ アプリなど、Release 相当の性能条件で再現・調査したいチームのデバッグ手順を改善できます。x64 MSBuild では設定により Whole Program Optimization が無効になるため、ビルド構成への影響も確認が必要です。

### アクションプラン
- Visual Studio 2026 / MSVC Build Tools 14.52 を利用する C++ チームは、要件と制約をドキュメントで確認する。
- x64 MSBuild では Release 構成の **Configuration Properties > Advanced > Use C++ Dynamic Debugging** を有効にして再ビルドし、WPO への影響を評価する。
- CMake 等では `cl.exe`、`lib.exe`、`link.exe` の `/dynamicdeopt` を検証する。Unreal Engine 5.6 以降では `WindowsPlatform.bDynamicDebugging = true` の利用可否を確認する。

### リファレンス
- [C++ Dynamic Debugging is now generally available](https://devblogs.microsoft.com/cppblog/c-dynamic-debugging-is-now-generally-available)

## How can I pass more than one parameter to `co_await`?

- **Blog:** Old New Thing
- **Author:** Raymond Chen
- **URL:** https://devblogs.microsoft.com/oldnewthing/20261112-00/?p=112851

### 要約
`co_await` 演算子に渡せるオペランドは1つなので、awaitable に優先度やタイムアウトなどの追加情報を直接渡すことはできません。awaitable と追加パラメーターを保持するラッパーを作り、そのラッパーの `await_*` メソッドから元の awaitable の処理へ値を渡す方法を示しています。

### 開発者にとって重要なこと
C++ コルーチンの待機動作を呼び出しごとに変更したい場合に、追加状態を awaitable のインターフェイスにまとめて扱えます。記事の例はラッパー方式の考え方を示しており、型や寿命の設計は実際の awaitable に合わせる必要があります。

### アクションプラン
- コルーチンに追加の待機パラメーターが必要な場合、オペランドをラップした awaitable として設計できるか検討する。
- ラッパーが `await_ready`、`await_suspend`、`await_resume` を適切に委譲し、参照するオブジェクトの寿命が待機中も保たれるか確認する。

- [How can I pass more than one parameter to `co_await`?](https://devblogs.microsoft.com/oldnewthing/20261112-00/?p=112851)
