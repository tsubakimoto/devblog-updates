## All or nothing: distributed transactions in Azure Cosmos DB

- **Blog:** Cosmosdb
- **Author:** Sergiy Smyrnov
- **URL:** https://devblogs.microsoft.com/cosmosdb/all-or-nothing-distributed-transactions-in-azure-cosmos-db

### 要約
Azure Cosmos DB for NoSQL で、パーティションキー、コンテナー、データベースをまたぐ書き込みを単一の原子的な分散トランザクションとしてコミットできる機能がパブリックプレビューになりました。すべての操作が成功するか、全体がロールバックされるため、従来アプリケーション側で補っていたサーガや補償トランザクションの一部を置き換えられる可能性があります。

### 開発者にとって重要なこと
複数の論理パーティションやコンテナーにまたがる更新の整合性を必要とする Cosmos DB for NoSQL アプリケーションに関係します。プレビュー機能のため、本番利用の可否や適用範囲は制約を確認して判断する必要があります。

### アクションプラン
- Cosmos DB for NoSQL を利用するチームは、複数リソース間の更新でサーガや補償処理を実装している箇所を洗い出す。
- パブリックプレビューの提供条件、制限、対象 API を記事で確認し、適用可能なら非本番環境で整合性・障害時の挙動を検証する。
- プレビューであることを踏まえ、本番導入はサポート条件と運用リスクを確認して判断する。

## Package.appxmanifest vs AppxManifest.xml

- **Blog:** Insidemsix
- **Author:** Howard Kapustein
- **URL:** https://devblogs.microsoft.com/insidemsix/package-appxmanifest-vs-appxmanifest-xml

### 要約
MSIX プロジェクトに見られる `Package.appxmanifest` と `AppxManifest.xml` の違いを解説しています。`Package.appxmanifest` は Visual Studio のパッケージ化プロジェクトで使われるテンプレート形式で、`$targetnametoken$` や `$targetentrypoint$` などのプレースホルダーを含みます。

### 開発者にとって重要なこと
MSIX のマニフェストを編集・生成する開発者にとって、テンプレートと最終的なマニフェストを混同しないための参考になります。Visual Studio のパッケージ化プロジェクトやビルド成果物の調査にも関係します。

### アクションプラン
- MSIX プロジェクトのソースと生成物で、どちらのマニフェスト形式を扱っているか確認する。
- トークンの置換やマニフェスト生成の詳細、編集時の注意点は記事本文で確認する。

### リファレンス
