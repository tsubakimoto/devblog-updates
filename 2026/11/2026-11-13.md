## Challenges of building machine learning compilers across varying hardware architecture

- **Blog:** DirectX
- **Author:** Rutvi Trivedi ほか（追加協力: Justin Stoecker、Sheil Kumar）
- **URL:** https://devblogs.microsoft.com/directx/machine-learning-compilers-challenges-hardware

### 要約
多様な GPU・NPU で性能と移植性を両立する機械学習コンパイラーの課題を解説しています。複数段階の IR、デバイス固有および非依存の最適化、演算融合、スケジューリングやメモリ管理を組み合わせる必要性を述べ、Windows ML と DirectX Compute Graph Compiler などを使った今後の方向性を予告しています。

### 開発者にとって重要なこと
ローカル AI や複数のハードウェアを対象とする開発では、単一演算の性能だけでなく、モデル全体の最適化やデバイス間の一貫性が課題になります。この記事は技術的な展望であり、具体的な利用可能機能や導入手順の発表ではありません。

### アクションプラン
- Windows 上でローカル AI を開発している場合、使用中のハードウェアごとの性能・互換性要件を整理する。
- コンパイラー選定では、演算対応だけでなく、融合・データ移動・フォールバックを含むモデル全体の挙動を評価する。
- 詳細な製品方針が必要な場合は、記事で案内されている Microsoft Ignite 2026 の BRK388 と今後の Windows ML / DirectX 発表を確認する。

### リファレンス
- [Challenges of building machine learning compilers across varying hardware architecture](https://devblogs.microsoft.com/directx/machine-learning-compilers-challenges-hardware)

## Microsoft Aion Instruct: Advancing local AI on Windows and expanding to GPU

- **Blog:** Foundry On Windows
- **Author:** Connor Al-Joundi
- **URL:** https://devblogs.microsoft.com/foundry-on-windows/aion-instruct-local-ai-windows-gpu

### 要約
Windows 上のオンデバイス言語モデルを Phi Silica から Aion Instruct に移行する計画と、対応 GPU への展開を発表しています。Aion Instruct は 2.3B パラメーターで、入力コンテキスト上限を 3.5K から 32K トークンに拡大し、Windows Insider への展開は 2026 年 11 月、一般提供は 2027 年 1 月を予定しています。

### 開発者にとって重要なこと
多くのアプリは変更不要とされていますが、カスタム LoRA、独自のシステムプロンプト、モデル出力の解析に依存するアプリは、モデルの挙動変更や透かしの導入による影響を確認する必要があります。対応 GPU の展開は段階的に進む予定です。

### アクションプラン
- Windows AI API を使うチームは、`aka.ms/tryaion` のパッケージで Aion Instruct を評価し、主要なプロンプト・出力処理・品質をテストする。
- ⚠️ Phi Silica のカスタム LoRA、独自プロンプト、出力文字列解析に依存する場合は、移行前に互換性を検証し、必要な変更を洗い出す。
- GPU 展開と Insider／一般提供の時期、移行ガイダンスの更新を Windows AI ドキュメントで確認する。

### リファレンス
- [Microsoft Aion Instruct: Advancing local AI on Windows and expanding to GPU](https://devblogs.microsoft.com/foundry-on-windows/aion-instruct-local-ai-windows-gpu)

## MSVC Build Tools Preview updates - November 2026

- **Blog:** Cppblog
- **Author:** Eric Brumer
- **URL:** https://devblogs.microsoft.com/cppblog/msvc-build-tools-preview-updates-november-2026

### 要約
MSVC Build Tools Preview の過去1か月の更新を紹介しています。v14.53 を対象とするプレビューには、C++14 の `[[fallthrough]]` 対応、ARM64・x64 のコード生成や最適化、リンカーと静的解析の改善、AddressSanitizer の新しいオプション、多数の不具合修正が含まれます。

### 開発者にとって重要なこと
新しい言語機能や ARM64／x64 の最適化を早期に試せる一方、対象はプレビュー版です。`/feature:sme`、自動ディスパッチ、`/WARNUNUSEDLIBS`、AddressSanitizer の `windows_shadow_top_down` など、一部の機能は実験的または明示的な有効化が必要です。

### アクションプラン
- MSVC の新機能や修正が必要な C++ チームは、Visual Studio Installer で対象アーキテクチャの Preview コンポーネントを追加し、非本番環境でビルドとテストを行う。
- ⚠️ プレビュー版への切り替え前に、CI と開発環境のツールセットを確認し、既存の製品ビルドへの影響を分離して評価する。
- 個別機能の制約や修正内容は記事とリンク先のチケットを確認し、問題があれば Visual Studio Developer Community に報告する。

### リファレンス
- [MSVC Build Tools Preview updates - November 2026](https://devblogs.microsoft.com/cppblog/msvc-build-tools-preview-updates-november-2026)

## How can I make it easier to use the helper class that lets me pass more than one parameter to `co_await`?

- **Blog:** Old New Thing
- **Author:** Raymond Chen
- **URL:** https://devblogs.microsoft.com/oldnewthing/20261113-00/?p=112856

### 要約
前回紹介した、追加パラメーターを awaitable とまとめるラッパー型を、呼び出し側が直接名前付けしなくて済むようにする方法を説明しています。awaitable に `start(priority)` のようなメソッドを設けて設定済みの補助 awaiter を返すことで、`co_await widget.start(priority)` と書けます。また、既定値で awaitable 自体を待機可能にする設計も示しています。

### 開発者にとって重要なこと
C++ コルーチンの待機時に優先度などの追加情報を渡したい場合、専用ラッパー型を隠して使いやすい API を提供できます。補助 awaiter が参照する元オブジェクトの寿命を、待機中も維持する設計が必要です。

### アクションプラン
- 追加パラメーターを受け取る awaitable を設計する場合、`start(...)` などのメソッドから補助 awaiter を返す API を検討する。
- `await_ready`、`await_suspend`、`await_resume` の委譲と、ラッパーが保持する参照先の寿命を確認する。
