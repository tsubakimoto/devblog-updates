## If the Windows documentation doesn’t list a particular technology as supporting an operation, does that mean that it doesn’t support it?

- **Blog:** The Old New Thing
- **Author:** Raymond Chen
- **URL:** https://devblogs.microsoft.com/oldnewthing/20261118-00/?p=112870/

### 要約
Windows のドキュメントに特定の技術がある操作をサポートすると記載されていないからといって、必ずしも非対応とは限りません。ドキュメントが説明するのは Windows が把握している範囲であり、サードパーティのネットワークプロトコルなど、Windows 側で判断できない対応状況もあります。

### 開発者にとって重要なこと
ドキュメントの一覧にないことだけを根拠に、特定のファイルシステムやネットワーク技術での動作可否を判断するのは危険です。対象の実装やプロトコルによって挙動が異なる可能性があります。

### アクションプラン
- ドキュメントに記載がない場合は即座に非対応と判断せず、対象の OS、ファイルシステム、ネットワークプロトコルで検証する。
- 仕様上の保証が必要な場合は、該当する API の説明と技術提供元の情報を併せて確認する。

### リファレンス
- [If the Windows documentation doesn’t list a particular technology as supporting an operation, does that mean that it doesn’t support it?](https://devblogs.microsoft.com/oldnewthing/20261118-00/?p=112870/)

## New Create and Apply wizards in SSMS (Preview)

- **Blog:** Azure SQL
- **Author:** Matt Hyon
- **URL:** https://devblogs.microsoft.com/azure-sql/new-create-and-apply-wizards-in-ssms-preview

### 要約
SSMS に、BACPAC／DACPAC の作成と適用を案内するプレビューウィザードが追加されます。DACPAC はスキーマのみ、BACPAC はスキーマと選択したテーブルデータを扱い、適用時にはスキーマ展開またはデータベースへのインポートを選択できます。BACPAC のインポートはユーザー定義オブジェクトのないデータベースを対象とし、既存テーブルへのデータのマージは行いません。

### 開発者にとって重要なこと
データベースのスキーマ移送や環境間の移行を、目的に応じてウィザードで進められます。プレビュー機能であり、DACPAC と BACPAC の適用動作には違いがあるため、移行手順を誤らないよう注意が必要です。

### アクションプラン
- プレビュー機能として検証環境で試し、必要なアクセス権と保存先（ローカルまたは Azure Blob Storage）を確認する。
- スキーマのみなら DACPAC、データも含めるなら BACPAC を選び、適用先の既存オブジェクトやデータへの影響を確認する。
- 実行ログを保存し、既存の移行手順と結果を比較してからチームでの採用を判断する。

### リファレンス
- [New Create and Apply wizards in SSMS (Preview)](https://devblogs.microsoft.com/azure-sql/new-create-and-apply-wizards-in-ssms-preview)
