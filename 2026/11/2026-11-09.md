## When one pass isn’t enough: agentic mode in Azure Content Understanding

- **Blog:** Foundry
- **Author:** Joe Filcik
- **URL:** https://devblogs.microsoft.com/foundry/when-one-pass-isnt-enough-agentic-mode-in-azure-content-understanding

### 要約
Azure Content Understanding のプレビュー機能として、文書内の表や図を横断して証拠を集め、計算・検証まで行う agentic mode が紹介されました。通常の standard mode より時間とモデル トークンを使うため、複雑な条件や長文書など、追加推論による精度向上が見込めるタスクに適しています。

### 開発者にとって重要なこと
文書抽出ワークフローで、標準的な一括抽出では難しい複数ページの集計、条件付き計算、図表の解釈などを扱いやすくなります。一方で、処理時間とコストが増えるため、すべての文書で agentic mode を使うのではなく、品質要件と費用の比較が必要です。

### アクションプラン
- Azure Content Understanding Studio で API version `2026-06-01-preview` と **Agentic Extraction** を選び、代表的な文書で standard mode と結果を比較する。
- コードから利用する場合は API version `2026-06-01-preview` を指定し、analyzer の `config` に `"workflow": "agentic"` を設定する。
- 精度改善がコスト・レイテンシに見合う複雑な文書に対象を絞る。詳細は記事のクイックスタートを参照する。

### リファレンス
- [When one pass isn’t enough: agentic mode in Azure Content Understanding](https://devblogs.microsoft.com/foundry/when-one-pass-isnt-enough-agentic-mode-in-azure-content-understanding)

## Windows App Development CLI v0.8: WinUI DevTools Experimental Preview

- **Blog:** Ifdef Windows
- **Author:** Chiara Mooney
- **URL:** https://devblogs.microsoft.com/ifdef-windows/windows-app-development-cli-v0-8

### 要約
Windows App Development CLI v0.8.0 では、実行中の WinUI アプリで要素やプロパティを調べ、変更を試し、コーディングエージェント向けコメントを残せる WinUI DevTools の実験的プレビューが追加されました。ほかに WinUI のパフォーマンス分析、C++ `.vcxproj` のビルド・実行・MSIX パッケージ化、チェックアウトごとの一意なアプリ ID、UI 録画の改善などが含まれます。

### 開発者にとって重要なこと
WinUI 3 の UI 調査や性能分析を CLI ベースの開発・エージェント作業に組み込めます。DevTools は実験的で、プロパティ変更は実行中だけの試行であり、ソースには反映されません。v0.8 では WebView2 を含むアプリの UI 調査停止や重複ビルド、署名などの修正と、CLI および診断ツールの DLL 読み込み強化・暗号ライブラリ更新も行われています。

### アクションプラン
- Windows アプリ開発チームは `winget install Microsoft.WinAppCLI` または `npm install --save-dev @microsoft/winappcli` で更新し、既存のワークフローへの影響を確認する。
- WinUI 3 アプリで `winapp run .` を試し、DevTools のプレビュー制約を踏まえて、採用前に必要な機能と挙動を検証する。無効化する場合は `winapp run . --devtools off` を使う。
- C++ プロジェクト、性能記録、複数チェックアウトの利用チームは記事の各ガイドで前提条件とオプションを確認する。

### リファレンス
- [Windows App Development CLI v0.8: WinUI DevTools Experimental Preview](https://devblogs.microsoft.com/ifdef-windows/windows-app-development-cli-v0-8)

## Do AI coding agents care about SemVer?

- **Blog:** Blog
- **Author:** Waldek Mastykarz
- **URL:** https://devblogs.microsoft.com/blog/do-ai-coding-agents-care-about-semver

### 要約
約 1,000 回の実験で、SemVer のバージョン表記だけでも一部の AI コーディングエージェントが依存更新をどれだけ確認するかに影響し、パッチ表記ではメジャー表記より確認を省く傾向が示されました。モデルによる差はありますが、確認を省いた結果、互換性を壊した更新がマージされる例もあり、バージョン番号はテストの代替にならないとしています。

### 開発者にとって重要なこと
エージェントに依存更新を任せる場合、SemVer ラベルへの信頼度はモデルごとに異なり、パッチ更新でも破壊的変更を見逃す可能性があります。ライブラリの保守者は SemVer を正確に保ち、利用側は更新の種類にかかわらず検証を必須にする必要があります。

### アクションプラン
- 依存更新ブランチすべてでテスト・ビルドを実行し、パッチ更新を含めて CI 成功をマージ条件にする。
- ライブラリのリリースでは SemVer と実際の互換性を一致させ、変更内容と移行情報を明記する。
- エージェント評価では利用するモデルとバージョン表記を変えたケースを含め、実行経過も確認する。

### リファレンス
- [Do AI coding agents care about SemVer?](https://devblogs.microsoft.com/blog/do-ai-coding-agents-care-about-semver)

## How do you run a query against data the database can’t read?

- **Blog:** Azure SQL
- **Author:** Anna Hoffman
- **URL:** https://devblogs.microsoft.com/azure-sql/how-do-you-run-a-query-against-data-the-database-cant-read

### 要約
Always Encrypted は、列暗号化キーをクライアント側で管理し、データベースサーバーが平文や鍵にアクセスせずに暗号化データを扱う仕組みです。secure enclave を使うとランダム化暗号化データにも範囲検索や LIKE などを実行できますが、暗号方式ごとの情報漏えい特性や性能コストを考慮する必要があります。

### 開発者にとって重要なこと
データベース管理者やクラウド運用者からも機密列を保護しながら、アプリケーションのクエリ機能を維持できるため、規制対象データを扱うシステムに有用です。Azure SQL Database の VBS enclave はより広く利用できますが現状では enclave attestation がなく、enclave バイナリの置き換えを想定する脅威モデルには Intel SGX と Azure Attestation の方が適すると説明されています。

### アクションプラン
- Azure SQL を利用するチームは Always Encrypted の対象列、クライアントドライバー、Azure Key Vault または managed HSM による鍵管理を設計する。
- secure enclave を採用する場合は、保護対象の脅威モデルと attestation の要件を確認し、VBS と Intel SGX の選択に反映する。
- 暗号化列のクエリ機能と性能は構成・ワークロードで異なるため、対象列を絞って実データに近い条件でベンチマークする。

### リファレンス
- [How do you run a query against data the database can’t read?](https://devblogs.microsoft.com/azure-sql/how-do-you-run-a-query-against-data-the-database-cant-read)
