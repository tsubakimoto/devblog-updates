## .NET MAUI Moves to CoreCLR in .NET 11

- **Blog:** .NET
- **URL:** https://devblogs.microsoft.com/dotnet/dotnet-maui-moves-to-coreclr-in-dotnet-11

### 要約
.NET 11 Preview 4 から、.NET MAUI の Android / iOS / Mac Catalyst で CoreCLR が既定ランタイムになります。これまでモバイル側で使われていた Mono から、サーバーやデスクトップで広く使われている CoreCLR へ揃える移行です。R2R や PGO による起動改善が期待される一方、大規模アプリでは起動時間やサイズが悪化するケースも報告されています。移行期間中は `UseMonoRuntime` で Mono に戻すこともできます。診断ツールや NativeAOT への道筋も、今回の変更の重要な背景として説明されています。

### 開発者にとって重要なこと
.NET MAUI でモバイルアプリを作っているチームに直結します。ランタイムの既定値が変わるため、性能、サイズ、互換性、診断の見直しが必要です。特に Android と iOS の既存アプリは、見た目より実測を優先すべき更新です。

### アクションプラン
- .NET 11 Preview 4 で Release ビルドを作成し、起動時間とパッケージサイズを .NET 10 と比較する。
- 依存ライブラリが CoreCLR で問題なく動くか、リフレクションや動的コード生成の有無も含めて確認する。
- ⚠️ 重大な回帰がある場合は一時的に `UseMonoRuntime>true</UseMonoRuntime>` を使い、本文の案内に従って issue を出す。

### リファレンス
- [.NET MAUI Moves to CoreCLR in .NET 11](https://devblogs.microsoft.com/dotnet/dotnet-maui-moves-to-coreclr-in-dotnet-11)

## Agent Skills in Visual Studio: Teach Copilot How Your Team Works

- **Blog:** Visual Studio
- **URL:** https://devblogs.microsoft.com/visualstudio/agent-skills-in-visual-studio

### 要約
Visual Studio で Agent Skills がサポートされたことを紹介する記事です。Agent Skills は、ビルド手順やボイラープレート生成、チーム固有のコーディング規約のような反復作業を Copilot に教える再利用可能な指示セットです。Visual Studio 内でスキルを作成・管理でき、solution-level または global/user-level に配置できます。スキルは自動検出され、適用時にはチャット上で見えるため、何が効いているか分かりやすい設計です。カスタム指示との違いや、MCP ツールとの補完関係も整理されています。

### 開発者にとって重要なこと
Visual Studio で Copilot を使っているチームにとって、作業手順の標準化と自動化を進めやすくなります。ビルド、レビュー、初期セットアップ、チーム独自ルールの適用を、個人の記憶ではなく共有スキルとして持てる点が大きいです。

### アクションプラン
- チームで繰り返している作業を洗い出し、Agent Skill 化できるものを優先する。
- `~/.copilot/skills/` または `.github/skills/` に置く構成を決め、共有範囲を整理する。
- Visual Studio Insiders で作成フローを試し、Release で使う前提の差分を確認する。

### リファレンス
- [Agent Skills in Visual Studio: Teach Copilot How Your Team Works](https://devblogs.microsoft.com/visualstudio/agent-skills-in-visual-studio)

## The case of the hang when the user changed keyboard layouts

- **Blog:** Oldnewthing
- **URL:** https://devblogs.microsoft.com/oldnewthing/20260513-00/?p=112318

### 要約
キーボードレイアウト切り替え時にアプリがハングする原因を追う Old New Thing の解説です。`WM_INPUTLANGCHANGE_REQUEST` を `DefWindowProc` に渡した際、背景スレッド上のウィンドウがメッセージを正しく処理していないと、入力言語変更が完了せず UI が止まります。ポイントは、ウィンドウを作ったスレッドはメッセージポンプを回す責任がある、という基本原則です。入力言語変更だけでなく、DDE やテーマ変更でも同じ問題が起こりえます。

### 開発者にとって重要なこと
Windows の UI スレッド設計に関わる実装者向けです。バックグラウンドスレッドでウィンドウを作る、メッセージを回さない、といった構成は一見動いても後で詰まる原因になります。

### アクションプラン
- ウィンドウを作成しているスレッドが必ずメッセージポンプを持つか確認する。
- UI でないなら、不要なウィンドウを作らない設計に見直す。

### リファレンス
- [The case of the hang when the user changed keyboard layouts](https://devblogs.microsoft.com/oldnewthing/20260513-00/?p=112318)

## General Availability of SharePoint Framework 1.23 - Advancing the modern developer experience

- **Blog:** Microsoft365dev
- **URL:** https://devblogs.microsoft.com/microsoft365dev/general-availability-of-sharepoint-framework-1-23-advancing-the-modern-developer-experience

### 要約
SharePoint Framework 1.23 の一般提供開始を告知する記事です。今回のリリースでは、list view command sets の grouping サポート、将来の SPFx CLI と open-sourced project templates のプレビュー、npm audit 問題への対応が含まれます。あわせて、SharePoint Online の Workbench 廃止予定や、Adaptive Card Extensions の Geolocation 非推奨も案内されています。SPFx を Microsoft 365 の主要な拡張モデルとして続けていく方針も強調されています。

### 開発者にとって重要なこと
SharePoint / Microsoft 365 向けの拡張を作るチームに直接影響します。特に廃止予定の機能を使っている場合は、移行計画を早めに立てる必要があります。CLI とテンプレートの変化は、今後の開発フローにも影響します。

### アクションプラン
- SPFx 1.23 へ上げる前提で、利用中の拡張と依存パッケージを棚卸しする。
- ⚠️ SharePoint Online Workbench と ACE の Geolocation を使っている場合は、2026-12-01 までの移行計画を立てる。
- 新しい SPFx CLI とテンプレートを試し、既存の scaffolding 手順を置き換えられるか確認する。

### リファレンス

## Introducing WinUI agent plugin for GitHub Copilot and Claude Code

- **Blog:** Ifdef Windows
- **URL:** https://devblogs.microsoft.com/ifdef-windows/build-native-windows-apps-with-ai-agents-for-winui-and-windows-app-sdk

### 要約
GitHub Copilot と Claude Code 向けの WinUI エージェントプラグインを紹介する記事です。WinUI / Windows App SDK 向けのエンドツーエンド作業を支援する agent と skills が含まれ、scaffold、build、run、test、iterate のループを効率よく回せます。XAML、MVVM、パッケージング、UI テスト、コードレビューなど、Windows アプリ開発に必要な作業がスキルとして分割されています。あわせて、Roslyn analyzer、検索ツール、WinRT メタデータ参照ツールなど、エージェントの精度を上げる補助ツールも提供されています。

### 開発者にとって重要なこと

### アクションプラン
- WinUI / Windows App SDK を扱うなら、Copilot CLI に plugin を入れてスキルの適用範囲を確認する。
- 新規アプリ作成、UI テスト、パッケージングのどこで効果が出るかをチームの作業で試す。
- ⚠️ まだ進化中のスキル群なので、出力結果と実ビルドの差分を確認しながら採用する。
