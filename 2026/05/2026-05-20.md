## Your dev loop is full of tribal knowledge

- **Blog:** Aspire
- **URL:** https://devblogs.microsoft.com/aspire/dev-loop-tribal-knowledge

### 要約
この投稿は、開発者体験が「後回しにしてよい作業」ではなく、実際には製品を出荷するための中核だと主張しています。ローカルループ、セットアップ、デバッグ、運用手順、エージェント向けの作業は、すべて開発速度に直結するという考え方です。記事では、口頭伝承や README、シェル履歴に散らばった知識を、再現可能で見つけやすい形にする必要性を説明しています。Aspire のダッシュボード、AppHost、CLI、リソースモデルを使うと、アプリの構成と操作を同じソースから扱えるようになります。結果として、チームが属人化した手順ではなく、明示的なモデルに基づいて開発・運用できるようになります。

### 開発者にとって重要なこと
ローカル開発環境を整備する開発者、複数サービスを扱うチーム、運用手順やデバッグ手順を標準化したい組織に関係します。特に、セットアップや再起動、マイグレーション、ヘルス確認が人依存になっているプロジェクトで効果が大きいです。

### アクションプラン
- 現在 README に埋もれている定型作業を洗い出し、Aspire のリソース操作に落とし込めるか確認する
- ローカルループで必要なログ・トレース・ヘルス確認の見える化を検討する
- チームで共有している「順番を知っている人だけができる作業」を、CLI やダッシュボードから再現可能にする

## Stop prompt injection from hijacking your agent, new security capabilities now released within Agent Framework

- **Blog:** Agent Framework
- **URL:** https://devblogs.microsoft.com/agent-framework/fides

### 要約
この投稿は、Agent Framework に追加された FIDES によるセキュリティ機能を紹介しています。主な狙いは、プロンプトインジェクションをヒューリスティックではなく、決定的なポリシーで防ぐことです。記事では、コンテンツに trust / confidentiality のラベルを付け、ツール呼び出しの前にポリシーを強制する仕組みを説明しています。さらに、untrusted コンテンツをメインモデルから隠す quarantined LLM と、コンテンツの自動伝播についても扱っています。サンプルや制限事項も明示されており、実運用に向けた検討材料が揃っています。

### 開発者にとって重要なこと
不特定の入力を読むエージェント、機密情報に触れるエージェント、公開先へ投稿するツールを持つエージェントを作る開発者に特に重要です。情報漏えいと不正なツール実行の両方を、モデル任せではなくポリシーで止めたい場合に関係します。

### アクションプラン
- 外部入力を扱うエージェントでは、trusted / untrusted と confidentiality の区別を設計に入れる
- 公開投稿、ファイル書き込み、秘密情報アクセスなどの高権限ツールにポリシー制約を追加する
- ⚠️ 実運用前に、approval_on_violation と quarantined LLM の運用コストを検証する

### リファレンス
- [Stop prompt injection from hijacking your agent, new security capabilities now released within Agent Framework](https://devblogs.microsoft.com/agent-framework/fides)
