## From Local to Production: Deploy Your Microsoft Agent Framework Agent with Foundry Hosted Agents

MAF でエージェントを作っているチームに直接関係します。プロトタイプを運用可能な形へ持ち上げる際の標準的な置き場として、Foundry Hosted Agents を検討する材料になります。認証、セッション永続化、ロールアウトの考え方を早めに揃えたい場合にも有用です。

### アクションプラン

- Responses / Invocations のどちらが自分のワークロードに合うか整理する。
- ⚠️ 監視、セッション保持、ID 管理、リリース手順が本文の前提に合うか確認してから導入判断する。

## Durable Workflows in the Microsoft Agent Framework

- **Blog:** .NET
- **URL:** https://devblogs.microsoft.com/dotnet/durable-workflows-in-the-microsoft-agent-framework

### 要約
Microsoft Agent Framework に追加された workflow programming model を紹介しています。executor と呼ばれるステップを組み合わせ、directed graph として複数のエージェントや作業単位をつなげる構成です。単純なチャット型のエージェントよりも、複数段の処理や耐障害性を意識したパイプラインを組みたいときに向いています。ワークフローの実行を durable に扱うための考え方が中心です。

### 開発者にとって重要なこと
複数ステップの AI 処理やオーケストレーションを作るチームに重要です。失敗時の再実行、状態保持、順序制御をフレームワーク側に寄せたい場合に関係します。単一エージェントより複雑な業務フローを AI 化したいときの設計材料になります。

### アクションプラン
- 既存のエージェント処理のうち、ステップ分割できるものを洗い出す。
- durable workflow で表現したい状態遷移や再開ポイントがあるか確認する。
- ⚠️ 本文を見て、現在の .NET / MAF 構成に追加できるか検証する。

## Why not have changes in API behavior depend on the SDK you link against?

- **Blog:** Oldnewthing
- **URL:** https://devblogs.microsoft.com/oldnewthing/why-not-have-changes-in-api-behavior-depend-on-the-sdk-you-link-against

### 要約
API の挙動を「リンクした SDK の版」によって変える案が、なぜ問題を起こしやすいかを説明しています。DLL や static library が異なる SDK でビルドされていると、同じプロセス内でも期待する挙動が揃わなくなります。さらに tail call や wrapper を挟むと、呼び出し元の SDK 判定自体が不安定になります。後方互換性や一貫した ABI のためには、SDK 依存の挙動変更は避けるべきだという話です。

### 開発者にとって重要なこと
Windows API を使う開発者だけでなく、ライブラリ設計や互換性を扱う人全般に重要です。見た目は単純な互換変更でも、複数コンポーネントが混在する現実のプロセスでは壊れやすいことを示しています。サイズやフラグのような明示的なバージョン判定のほうが安全です。

### アクションプラン
- API の互換設計で、リンク時 SDK 依存の分岐を入れていないか確認する。
- 既存のバージョン判定は、明示的なサイズやフラグに寄せられないか見直す。
- ⚠️ DLL / static library が混在する構成では、本文の理由を踏まえて挙動変更の影響を再評価する。

### リファレンス
- [Why not have changes in API behavior depend on the SDK you link against?](https://devblogs.microsoft.com/oldnewthing/why-not-have-changes-in-api-behavior-depend-on-the-sdk-you-link-against)
