## How AI coding agents actually use your technology

- **Blog:** Blog
- **URL:** https://devblogs.microsoft.com/blog/how-ai-coding-agents-actually-use-your-technology

### 要約
この投稿は、AI コーディングエージェントが SDK、CLI、API、ドキュメント、MCP サーバーをどう利用するかを扱っています。人間の開発者とは違い、エージェントの挙動は見えにくく、何を参照しているのか分かりづらい点を問題提起しています。前回の紹介で触れた AX スタック（model / harness / agent extensions）を踏まえ、エージェントが技術をどう消費するかを整理しています。要点は、AI エージェント向けには人間向けとは別の設計視点が必要だということです。全文で具体例と考え方を確認する価値があります。

### 開発者にとって重要なこと
SDK、API、ドキュメント、MCP などを提供するチームは、利用者が人間だけでなく AI エージェントにも広がる前提で考える必要があります。特に、説明の分かりやすさ、呼び出しやすさ、機械可読性が重要になります。

### アクションプラン
- ドキュメント、サンプル、MCP/CLI/API の呼び出し方がエージェントにとって分かりやすいか確認する
- AI エージェントが実際にどの経路で技術を見つけて使うかを検証する
- テレメトリやログで、エージェント利用を追跡できるか見直す
- ⚠️ AX スタックの具体策は本文参照で、実装判断は自分のツール群に当てはめて進める

### リファレンス
- [How AI coding agents actually use your technology](https://devblogs.microsoft.com/blog/how-ai-coding-agents-actually-use-your-technology)

## Deployment Operations, Requests and Queue

- **Blog:** Insidemsix
- **URL:** https://devblogs.microsoft.com/insidemsix/deployment-operations-requests-and-queue

### 要約
PackageManager API が deployment engine に送る request と、そこから生成される deployment operation の関係を説明する技術記事です。Move Package、Stage Package、Repair Package などの操作例を挙げながら、内部的なキュー処理と並行実行の仕組みを解説しています。staging には同時実行数の制限があり、処理はシステム状況に応じてスロットリングされます。デプロイメントのログやテレメトリにも触れる、かなり内部寄りの内容です。Windows の配布・修復・パッケージ処理に関わる人向けの深掘り記事です。

### 開発者にとって重要なこと
Windows の deployment、packaging、servicing、診断に関わるエンジニアにとって有用です。アプリ開発者全般よりも、プラットフォーム側や運用・分析側のチームに影響します。

### アクションプラン
- PackageManager や deployment ログを扱うチームは、request と operation の対応を把握する
- 並行実行や staging の制限が、処理遅延やスループットにどう影響するか確認する
- 診断や監視を作る場合は、この用語体系に合わせてログ解釈を整理する

### リファレンス
- [Deployment Operations, Requests and Queue](https://devblogs.microsoft.com/insidemsix/deployment-operations-requests-and-queue)
