## SQL MCP Server as an App Service

- **Blog:** Azure SQL
- **URL:** https://devblogs.microsoft.com/azure-sql/sql-mcp-server-app-service

### 要約
SQL MCP Server を AI エージェントと SQL データベースの間に置くことで、エージェントは直接 DB に触れずに制御された API 面からデータを扱えるようになります。基盤は Data API builder (DAB) で、キャッシュ、テレメトリ、認証、エンティティ単位の抽象化を提供します。これにより、エージェントは組織のガードレールの範囲内で動作しやすくなり、物理的なスキーマへの直接依存も避けられます。DAB は REST と GraphQL も同じ設定から提供できるため、この仕組みは MCP 専用の話にとどまりません。詳細な構成や制約は本文参照です。

### 開発者にとって重要なこと
Azure SQL と AI エージェントを組み合わせるアプリで、データアクセスの安全性と運用性を高める話題です。直接接続よりも、権限・監査・キャッシュの管理を API 層に寄せたいチームに関係します。DB スキーマ変更の影響を下げたい場合にも有用です。

### アクションプラン
- Azure SQL を使う AI/agentic ワークロードがあるか確認し、直接 DB 接続の置き換え候補を洗い出す。
- DAB ベースの API 層で認証、キャッシュ、テレメトリをどう標準化するか検討する。
- ⚠️ 本文を確認して、既存のスキーマ依存やアクセス制御に影響がないか評価する。

## There is no Install - it's 'Stage' and 'Register'

- **Blog:** Insidemsix
- **URL:** https://devblogs.microsoft.com/insidemsix/there-is-no-install-its-stage-and-register

### 要約
MSIX では「インストール」という言い方が正確ではなく、「stage」と「register」が基本概念だと説明しています。PackageManager API を通じた deployment request が、パッケージの追加・削除・その他の管理操作を表します。つまり、MSIX の配布は単純なインストーラー実行ではなく、システムにパッケージを staging し、ユーザーに registration する流れで理解する必要があります。この記事は、MSIX のアーキテクチャを正しく把握するための概念整理です。具体的な運用詳細は本文参照です。

### 開発者にとって重要なこと
MSIX を使う Windows アプリの配布や更新を扱うチームに重要です。用語の違いは、配布フロー、トラブルシュート、API の理解に直結します。パッケージ管理の自動化やサポート対応でも前提知識になります。

### アクションプラン
- MSIX の運用ドキュメントや社内用語で「install」を使っている箇所を見直す。
- PackageManager API を使う自動化があるなら、stage/register のどちらを実行しているか確認する。
- ⚠️ 配布・更新フローの理解ずれがある場合は、本文を基準に手順書を修正する。

### リファレンス

## Introducing Apache Arrow Support in mssql-python

- **Blog:** Python
- **URL:** https://devblogs.microsoft.com/python/introducing-apache-arrow-support-in-mssql-python

### 要約
mssql-python が SQL Server データを Apache Arrow 形式として直接取得できるようになりました。これまでのように大量の Python オブジェクトを経由せず、Polars、Pandas、DuckDB など Arrow 対応ライブラリへより効率的に渡せます。大規模データ取得時の GC 負荷やメモリ消費を抑えやすくなるのがポイントです。この機能はコミュニティ開発者の貢献で追加されました。Arrow ネイティブな分析パイプラインを使う開発者に向けた更新です。

### 開発者にとって重要なこと
SQL Server データを分析基盤やデータサイエンス環境に流し込むチームに直接効きます。特に大量行の読み取りがボトルネックだった場合、性能改善の候補になります。既存コードが Arrow 対応ライブラリなら、恩恵を受けやすい変更です。

### アクションプラン
- mssql-python で大量取得している処理があるなら、Arrow 経路に切り替えられるか評価する。
- Polars / Pandas / DuckDB などの受け側が Arrow ベースで動くか確認する。
- ⚠️ メモリ使用量とシリアライズ経路の違いがあるため、本文の利用条件を読んでから導入する。

- [Introducing Apache Arrow Support in mssql-python](https://devblogs.microsoft.com/python/introducing-apache-arrow-support-in-mssql-python)
